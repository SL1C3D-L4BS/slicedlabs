# Episode records SL-EP-049 to SL-EP-060

Records for the twelve infrastructure episodes of Volume 03 that work orders WO-020 and WO-024 to WO-034 built
(SL-VOL-03-SPEC records 049-060; master plan section 6.1 record fields). The registry
`registry/SL-REG-002-episodes.json` is authoritative (master plan section 6.3 rule 1): every episode below is still
`Planned` there, and this builder changes no status. The founder runs `evidence-record` and `ep-advance` after the
merge (SL-PLAN-003, ADR-0007), which can reach Demonstrated; Accepted waits for episode 020 (ADR-0003; master plan
section 6.2).

Machine under test (measured, `build/acceptance/*.log`): clang 23.1.3, gcc 16.2.1 with libstdc++-16, cmake 4.4.4, ninja 1.13.2, just 1.59.0, Python 3.14.8, Arch Linux. Nothing here was run on Windows, on GitHub
Actions or on a GPU device. Evidence files `evidence/WO-020.json` and `evidence/WO-024.json` to `evidence/WO-034.json`
do not exist yet: the founder records them after the merge (`evidence/README.md`), so every "evidence/WO-NNN.json"
pointer below is pending founder close-out.

Observed exit codes and wall times below were measured in one session on the working tree of WO-034, one run of each
cited recipe. Recipes that `check-full` runs (tidy, analyze, sanitize-proof, hardening, neg-tidy and `ci-local`) are
cited through `check-full`, not repeated alone.

## SL-EP-049 — Automated formatting

### Done

- `just fmt-check-all` runs `fmt-check` (C++ through clang-format, include order kept by `IncludeBlocks: Preserve`) and
  then `tools/format/check.py --check` over CMake, Python, shell, JSON and Markdown front matter (key order of
  `docs/templates/DOC.md`), and `shfmt -d` when installed (WO-024). `just fmt-all` is the mechanical fixer.
- `just neg-format-all` plants one defect per kind (cmake, python, shell, json, frontmatter) in a copy of the tree and
  requires `fmt-check-all` to fail naming the kind and file; a fix round trip then proves `fmt-all` repairs fixable
  defects (`tests/gates/neg_format_all.sh`; governance rule: every gate has a negative test).
- The 171 Python lines over 120 characters found at delivery were wrapped on 2026-10-18 (AST-identical); `tools/format/allow.txt` has no entries
  (measured: 37 entries).

### Decisions

ADR-0004 (tooling is Python stdlib only, so the checker uses no third-party formatter for Python, JSON or front
matter). No new ADR for the C++ include-order choice: it is a `.clang-format` setting (WO-024).

### Acceptance

- `just fmt-check-all`: exit 0 observed (1 s wall, this run).
- `just neg-format-all`: exit 0 observed (3 s wall, this run).
- `just fmt-check`: part of `fast` and runs first inside `fmt-check-all`.

### Evidence

- `evidence/WO-024.json`: pending founder close-out.

### Open issues

  without shfmt the shell check is weaker.
- Format is checked on Linux only; Windows line-ending behaviour is untested (ADR-0006).

cmake 4.4.4, ninja 1.13.2, just 1.59.0, Python 3.14.8, Arch Linux. Nothing here was run on Windows, on GitHub Actions,
on a GPU device, with a window or an input device, or on a big-endian host.

Honest limits of the whole volume, repeated per episode where they bite:

- Headless only: the runtime opens no window and reads no input device (ADR-0002, ADR-0028); windowing, input routing
  and presentation are Volumes 06 and 07 (V06-4, V07-1).
- Determinism is class D1 for one binary: per-tick state hashes are equal for 1, 2, 4, 8 and 16 workers, serial
  versus parallel, resume from a snapshot and replay of recorded inputs. The clang-versus-gcc comparison is recorded in
  `hash-matrix.json` and never sets an exit code; D2 and above (cross-compiler, cross-platform) are Volume 17
  (SL-ARCH-012, not written).
- Linux only; Windows is unverified (ADR-0006) and the platform layer has one implementation.
- Wall time is recorded, not gated: every number below is one observation on one machine, taken while nothing else ran in
  the tree, never a budget. Performance cases are work-bound counters (upstream allocations per steady frame,
  archetypes visited, steals, log events); benchmarks are Volume 16.
- The demo runs in Debug because its failpoints and leak sites exist only there; a Release run of the same scene appears
  in `runtime-determinism` (the gcc-release cells).
- The WO-109 documented limits stand: the startup RFP0 sweep covers allocation visits 1 and 3 and not visit 2 (the
  entity allocator's `std::pmr` page list aborts by design, ARCH3-R025); a fault in the first host frame has no recovery
  baseline and ends in `recovery_failed`; the pending entity value depends on which worker opened a buffer first while
  the entities it resolves to do not.
- The tick-0 note: a system's first run reads the change floor one before tick 0, so stamps written at tick 0 are
  visible to it (R128); a restore rewinds the logical tick and every last run together.
- The RFP0 note: allocation failure is injected at the memory root or around world operations only, never inside the job
  system, which allocates nothing tracked.
- Seams V02-1, V06-1 to V06-5, V07-1, V07-2, V07-4, V16-1, V16-3, V17-2, V17-4, V17-6, V17-8, V19-1 to V19-3 and V26-1

## SL-EP-081 — Runtime lifecycle states

### Done

- The runtime lifecycle: states and legal transitions, `start` running the platform check, memory root, tag freeze, registry freezes, job system, frame scheduler and world in order and unwinding in reverse on a failed step; shutdown joins every thread and ends with zero tracked bytes (WO-096).
- Recovery: a recovery point is a snapshot plus the systems' last runs; a fault under the restore policy rewinds the world, the logical tick and the last runs (wall time goes on), under the stop policy the runtime stops; restore and shutdown discard undelivered background results. The swap protocol and `runtime_abi_digest` are in, with rollback through the same restore (WO-096, WO-109).
- The first recovery baseline is taken at the end of the first host frame, so a fault in that frame has no baseline and ends in `recovery_failed` (WO-109, deviation record).

### Decisions

ADR-0028 (lifecycle, recovery, swap protocol and the P0 gate) and ADR-0021 (Volume 05 starts before Volume 02, Demonstrated cap).

- `just runtime-test life`: exit 0 observed (8 s wall, inside `just runtime-gate`, this run); the primary work order WO-096, supporting WO-072, WO-075, WO-076, WO-109.

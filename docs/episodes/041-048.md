# Episode records SL-EP-041 to SL-EP-048

Records for the eight Foundation episodes of Volume 03 that work orders WO-013 to WO-021 built (SL-VOL-03-SPEC records
041-048; master plan section 6.1 record fields). The registry `registry/SL-REG-002-episodes.json` is authoritative

The founder runs `evidence-record` and `ep-advance` after the merge (SL-PLAN-003, ADR-0007), which can reach

Machine under test (measured, `build/acceptance/*.log`): clang 23.1.3, gcc 16.2.1 with libstdc++-16, cmake 4.4.4,
ninja 1.13.2, just 1.59.0, Python 3.14.8, Arch Linux. Nothing here was run on Windows or on a GPU device.
Evidence files `evidence/WO-013.json` to `evidence/WO-021.json` do not exist yet: the founder records them after the
merge (`evidence/README.md`), so every "evidence/WO-NNN.json" pointer below is pending.

## SL-EP-043 — Define the C++23 baseline

### Done

- `cmake/features/required-cxx23.txt` lists 21 required C++23 feature ids, each a compile-and-run test in
  `cmake/features/cxx23/<id>.cpp`; `cmake/SlFeatures.cmake` configures the battery and stops configure with a quoted
  message when a listed test file is missing or fails (WO-015; master plan section 1.5: C++23 baseline proven by
  toolchain tests).
- `cmake/features/matrix.json` records the measured result per feature, clang and gcc; the 22 C++23 entries pass on both
  (21 required, `stdfloat` deferred). `just features-check` fails only when a C++23 result differs from the matrix.
- `cmake/features/deferred-cxx23.txt`: `stdfloat` fails on both compilers (`__cpp_lib_stdfloat` missing) and is tested,
  reported and never fatal.
- `just neg-feature-removed` deletes `if_consteval.cpp` in a copy and requires configure to fail with the exact message;
  `just neg-feature-unlisted` requires an unlisted test file to be refused.

### Decisions

promoting C++26 features is still open).

### Acceptance

- `just neg-feature-unlisted`: part of `negatives` in `check`; not repeated here.

### Evidence

## SL-EP-048 — Lock dependencies reproducibly

### Done

- `deps/deps.json` (manifest) and `deps/deps.lock.json` (one lock, schema `sl-deps-lock/1`, manifest hash recorded)
  describe 5 packages: doctest 2.5.3, cpm 0.43.2, and Tier B ranges for vulkan, slang and spirv-val (WO-017; ADR-0002).
- `tools/deps/sldeps` (`check`, `lock`, `sync-vcpkg`, `vendor`, `register`, `cpm-url`, `lock-refresh`) computes and
  verifies hashes offline; `pending` and `unpinned` are derived at check time, never stored (WO-017).
- Vendored: `third_party/doctest` (sha256 `cfd518a3...1421`, copied from the Arch package, `verified_upstream: false`)
  and `third_party/cpm` (CPM 0.43.2, trust on first use); `third_party/*/MANIFEST.json` are generated from the lock.
- Four providers resolve through `sl_require()`: vendored and system (WO-018), cpm offline against a `file://` archive and
  vcpkg against a fixture toolchain (WO-019). A hash mismatch never falls through to the next provider.
- `just deps-register` writes `registry/views/SL-REG-005-dependencies.md` from the lock (WO-021); the view lists
  doctest cpm and vcpkg providers as unpinned.
- Founder-only network recipes exist outside the gate: `deps-lock-refresh`, `deps-cpm-smoke`, `deps-vcpkg-smoke` refuse
  to run without `SL_DEPS_ALLOW_NETWORK=1` (agents never fetch; ADR-0002).

### Decisions

ADR-0002 (one policy, one lockfile, four providers), ADR-0004 (stdlib-only tooling).

### Acceptance

- `just neg-deps`, `just neg-deps-missing`, `just neg-deps-unpinned-provider`, `just neg-vcpkg-absent`,
  `just deps-provider-test vendored`: part of `negatives` in `check`; not repeated here.

# WO-081 deviations: foundational allocators (episode 084)

Builder record for allocators.hpp, src/alloc_{arena,stack,pool,frame,sync,general}.cpp, the six alloc_*_test.cpp
files and the neg-runtime-poison gate. SL-ARCH-003 was not edited.

## stack_resource: LIFO is enforced inside marker scopes; outside them releases are deferred

- Decision: inside a push_marker scope a release of anything but the top block is SL_ASSERT ("out-of-order release")
  and leaves the block allocated. With no scope open, a release that is not the top marks the block freed (filled and
  poisoned); its space returns once every block above it is released. pop_marker frees its whole scope.
- Why: the brief asks for both "release must be LIFO" and "passes run_allocator_contract", and the contract (not in
  paths_allowed) releases in FIFO and random order. Strict LIFO everywhere cannot pass it.
- Where: engine/runtime/src/alloc_stack.cpp `stack_resource::release`, `pop_freed`.
- Rule or table: ARCH3-R048, assertions list ("an out-of-order stack_resource free").

## owner_thread_resource: one base for the owner check, lifted by synchronized_resource

- Decision: arena_resource, stack_resource, pool_resource and frame_arena derive `mem::owner_thread_resource`
  (allocators.hpp): the owner is a `std::atomic<std::thread::id>` captured at construction; `check_owner(bind)`
  SL_DEBUG_ASSERTs it on every call (mark, used, free_space_stats and check_free_list included) and binds an unbound
  owner when bind is true. synchronized_resource calls the protected `share()` on an owner-thread inner resource,
  which lifts the check for good; its mutex then orders every call. When a test handler returns from the assertion the
  call goes on (no wrong_thread result). The check is compiled out with NDEBUG, as SL_DEBUG_ASSERT is. Its code is in
  alloc_sync.cpp (no seventh source).
- Why: synchronized_resource exists to share owner-thread allocators; without lifting the check every wrapped call from
  another thread would assert. An atomic owner keeps a misuse a captured assertion, not a data race.
- Where: allocators.hpp `owner_thread_resource`; alloc_sync.cpp `check_owner`, `synchronized_resource` constructor.
- Rule or table: ARCH3-R049, ARCH3-R175, `thread_safety`. Open for WO-085: make_report is any-thread, but
  free_space_stats of an unwrapped pool asserts the owner; WO-085 reads it on the owner thread or through
  synchronized_resource.

## The allocators visit no failpoint

- Decision: none of the six visits RFP0; an upstream error (out_of_memory from a tracking_resource under RFP0) is
  returned unchanged. There is therefore no `#if SL_RUNTIME_FAULTS` branch in the alloc sources.
- Why: tracking_resource already visits RFP0 at its try_allocate; a second visit per call in each layer would make
  "the Nth call" depend on the allocator stack.
- Where: engine/runtime/src/alloc_*.cpp.
- Rule or table: `failpoints` RFP0.

## arena_resource details

- Decision: blocks are taken at first use, carry a 32-byte header (intrusive chain, index, end) and are
  max(block_bytes, request + header + alignment) bytes, so a large request gets an oversized block. Blocks after the
  current one are empty, so a marker {block index, offset} covers every later allocation; a block too small for a
  request is skipped. rewind and reset keep every block. With capacity_bytes != 0 the blocks never exceed it (the last
  block shrinks to what is left, else arena_exhausted). release of the last allocation moves the end back; any other
  release, in Debug and sanitizer builds, checks `owns(p)` (SL_DEBUG_ASSERT otherwise) and fills and poisons the
  range. mark() with no block is {0, 32}. used() counts alignment padding. Members beyond the brief: `reserved()`,
  `upstream_allocations()`, `owns(p)`, `free_space_stats()`.
- Why: the brief fixes the interface but not the block layout; growth must count upstream blocks for WO-089.
- Where: alloc_arena.cpp `arena_resource::grow`, `allocate_unchecked`, `release_unchecked`, `rewind_unchecked`.
- Rule or table: ARCH3-R048, `limits` arena_block_bytes_default.

## stack_resource details

- Decision: one buffer of capacity_bytes (rounded up to 16) is taken at the first allocation or push_marker; each block
  and marker is a 48-byte entry in front of its offset (previous top, entry below, enclosing marker, size, kind,
  freed). Alignment is computed on addresses. push_marker returns `result<void>` (arena_exhausted when full);
  pop_marker without a scope is SL_ASSERT. A double release or a pointer outside the stack is SL_DEBUG_ASSERT. Members
  beyond the brief: `depth()`, `used()`, `capacity()`, `free_space_stats()`.
- Why: push_marker can run out of room; the brief gives no signature for it.
- Where: alloc_stack.cpp `push_entry`, `push_marker`, `pop_marker`.
- Rule or table: ARCH3-R048, `errors` arena_exhausted.

## pool_resource details

- Decision: block_size < 16 or an invalid block_align is SL_ASSERT in the constructor, then clamped (16; 16). Blocks
  are spaced by stride = block_size rounded up to max(block_align, 16). A request above block_size or aligned beyond
  the pool's alignment is invalid_argument; a malformed alignment stays bad_alignment. A slab is 65536 bytes with a
  1056-byte header (chain plus a free bitmap and a scratch bitmap, one bit per block), blocks from the first
  block_align boundary after it; a block that does not fit one 64 KiB slab gets a slab of exactly one block. Fresh
  slabs push their blocks so the lowest address is served first. free_space_stats reports bytes (free blocks x stride,
  longest free run x stride). The owner of a released block is found by walking the slab list. Members beyond the
  brief: `block_size()`, `block_align()`, `stride()`, `slabs()`, `total_blocks()`, `free_blocks()`,
  `check_free_list()` (RT-INV-ALLOC-03's exactly-once proof).
- Why: the constructor cannot return a result; the bitmap gives both the fragmentation figure of ARCH3-R052 and the
  Debug double-release check without a side allocation.
- Where: alloc_pool.cpp `pool_resource` constructor, `grow`, `try_allocate`, `release`, `check_free_list`.
- Rule or table: ARCH3-R048, ARCH3-R174, `limits` pool_slab_bytes (one-block slabs above it), pool_min_block_bytes.

## frame_arena details

- Decision: frame_arena(upstream, workers, block_bytes, tag) derives owner_thread_resource; each set is a vector of
  workers + 1 arena_resource built once. Its own try_allocate and release use the owner arena (k = workers) of the
  current set; release goes to the set that owns the pointer. flip makes the other set current and resets it, so the
  set reset is the one used two flips ago; the per-worker arenas of that set are unbound (also at construction) and
  bind to the thread of their next allocation; the owner arenas stay bound to the owner. for_worker(k > workers) is
  SL_ASSERT and returns the owner arena. Members beyond the brief: `workers()`, `current_set()`, `flips()`,
  `upstream_allocations()` (sum over both sets) and `used()` (current set).
- Why: the brief names the sets and the flip rule but not the resource interface of the frame_arena itself, which the
  contract needs.
- Where: alloc_frame.cpp `frame_arena::try_allocate`, `release`, `flip`.
- Rule or table: ARCH3-R050, ARCH3-R051, `thread_safety` frame_arena rows, `limits` frame_arena_block_bytes.

## synchronized_resource and general_resource details

- Decision: synchronized_resource takes the default tag and registry of the inner resource; free_space_stats is read
  under the mutex. general_resource passes the caller's tag, the effective size and the effective alignment to
  try_allocate_from and release_to, fills 0xCD and 0xDD itself, and treats a nullptr upstream as
  std::pmr::new_delete_resource().
- Why: the contract allocates with default_tag(); blocks must leave and return with the same size and alignment.
- Where: alloc_sync.cpp `synchronized_resource`; alloc_general.cpp `general_resource`.
- Rule or table: ARCH3-R043, ARCH3-R048.

## Fills and poisoning granularity

- Decision: fresh arena blocks, pool slabs and the stack buffer are poisoned whole and each allocation unpoisons
  exactly its bytes; released and reset ranges are unpoisoned, filled 0xDD and poisoned (arena ranges rounded up to
  16 bytes, the next block starts on 16). Memory is unpoisoned before it goes back to the upstream. A free pool block
  keeps its link in its first bytes and stays poisoned; the link is unpoisoned only while read or written.
- Why: the upstream (tracking_resource) writes its own fill into returned memory, and ASan reports any access to a
  poisoned byte.
- Where: alloc_arena.cpp `scrub`; alloc_stack.cpp `scrub`; alloc_pool.cpp `push_free`, `read_link`.
- Rule or table: ARCH3-R046.

## Constants in allocators.hpp

- Decision: `pool_slab_bytes`, `pool_min_block_bytes`, `arena_block_bytes_default` and `frame_arena_block_bytes` are
  `inline constexpr std::size_t` in allocators.hpp with the `limits` names and values.
- Why: ARCH3-R174 asks for the table's values; the defaults of the constructors use them.
- Where: allocators.hpp.
- Rule or table: `limits`.

## Tests and the gate

- Decision: tests create threads with std::thread (RT-INV-ALLOC-04 workers, ALLOC-05 churn, ALLOC-06 intruders) and
  join them before the owner continues. The owner-check cases (ALLOC-06, the worker-binding case of ALLOC-04 and the
  pool double-release case) skip with a message under NDEBUG. ALLOC-05 runs 20000 operations per thread (2000 for the
  contract case) times SL_RUNTIME_STRESS_SCALE, at least 1000. neg_runtime_poison.sh also runs a control (the read
  before reset must exit 0 with no ASan output), takes the compiler and flags of alloc_arena.cpp from
  build/ci-asan/compile_commands.json, links libsl_runtime.a, libsl_fabric.a, libsl_core.a and -lstdc++exp with the
  default linker, and runs with ASAN_OPTIONS=detect_leaks=0:halt_on_error=1:exitcode=66.
- Why: the platform thread_factory is not needed to show allocator invariants (as in WO-080); the owner check does not
  exist in Release; a control proves the planted program is not failing for another reason.
- Where: tests/unit/runtime/alloc_*_test.cpp, tests/integration/runtime/alloc_sync_churn_test.cpp,
  tests/gates/neg_runtime_poison.sh.
- Rule or table: ARCH3-R016, ARCH3-R046.

## WO-108: gcc -fanalyzer on the churn test

- Decision: the ALLOC-05 churn test holds its blocks in a value-initialised `std::array<held, max_held>` with a
  count instead of a `std::vector`, clears a slot on release, and `intact()` rejects a slot whose pointer is null.
- Why: gcc -fanalyzer reported a null dereference and an uninitialised `held::p` at alloc_sync_churn_test.cpp:76;
  the invariant is now visible by construction, with no pragma or suppression. No allocator behaviour changed.
- Where: tests/integration/runtime/alloc_sync_churn_test.cpp.
- Rule or table: none (test code only).

# WO-095 deviations: runtime snapshots and state hash (episode 098)

## Restore rebuilds values from zero bytes and the snapshot fields; snapshotted values are trivially copyable

- Decision: take writes each component value as the reflect codec's encoding of its `snapshot` fields (a component
  without reflection writes zero fields); restore zero-fills aligned storage and decodes each row into it, then hands
  the rows to `world::restore_from`. A component that is not trivially relocatable in an archetype with rows, or such a
  resource, is invalid_argument at take and snapshot_corrupt at restore. Fields without the snapshot flag come back as
  zero bytes.
- Why: the brief names the selected-field codec but not how a value is built from it; without a construct hook in
  `component_info` a byte image plus decoded fields is the only rebuild that does not run arbitrary constructors, and it
  is only sound for trivially copyable types.
- Where: engine/runtime/src/snapshot_take.cpp `check_rebuildable`, engine/runtime/src/snapshot_restore.cpp
  `value_block::fill`, `stage_chunk`.
- Rule or table: ARCH3-R143, R145, ADR-0026.

## Resources: component-typed resources are snapshotted, runtime-owned ones stay

- Decision: a resource whose C++ type is a registered component (`find_key` on its type key) is snapshotted and hashed
  by key and component id. Any other resource (event channels and other runtime-owned state) is neither snapshotted
  nor hashed and stays in the target world; restore merges it by key with the snapshot's resources. The snapshot wins
  on a shared key, and a component-typed resource the snapshot does not record is dropped.
- Why: the brief lists resources but resource slots carry no reflection; the component registry is the only type
  description available. Event channels are restored by their own contributor (WO-092), not as values.
- Where: engine/runtime/src/snapshot_hash.cpp `resource_component`, engine/runtime/src/snapshot_take.cpp `write_world`,
  engine/runtime/src/snapshot_restore.cpp `stage_resources`.
- Rule or table: ARCH3-R143, R146.

## RFP8 is one visit per save, before the write

- Decision: `save` visits RFP8 once, before `file_access::atomic_write`; when it fires save returns io_error and no
  primitive runs (a crash before the first primitive). Crashes after each primitive come from the faulty vfs.
- Why: WO-078 put RFP8's site in snapshot::save and left atomic_write without a failpoint.
- Where: engine/runtime/src/snapshot_io.cpp `save`.
- Rule or table: ARCH3-R147, `failpoints` RFP8.

## Format details: type digest, trailer first, minor ignored, length-prefixed columns

- Decision: SLRS/1 as documented in snapshot.hpp. The type digest is a state_hasher over "sl-rt-type/1", the
  component's name, size, alignment, relocatability and, when reflected, the reflected name and each field's name,
  offset, size, kind and flags. The SHA-256 trailer is checked before the magic and version, so any single-bit flip is
  snapshot_corrupt; a valid trailer with major != 1 is snapshot_version. The minor version is read and ignored. Each
  value column is prefixed by its u32 byte length.
- Why: the brief names the sections, not their encoding or check order.
- Where: engine/runtime/include/sl/runtime/snapshot.hpp, engine/runtime/src/snapshot_format.cpp `type_digest`,
  `parse_snapshot`.
- Rule or table: ARCH3-R144.

## Extra surface

- Decision: beyond the brief, `snapshot::from_bytes`, the `frame()`, `runtime_abi_digest()` and `schedule_digest()`
  accessors, the `detail` writer, reader, parser and hash helpers in the public header, the `hash_breakdown` sentinels
  `no_archetype` and `no_component`, an entities part and one rows part per archetype in the breakdown.
  `first_difference` compares parts only; the contributors digest is compared on its own.
- Why: load needs from_bytes; the tests need the parser (bit flips under a resealed trailer) and the sentinels name the
  parts that are not one (archetype, component) column.
- Where: engine/runtime/include/sl/runtime/snapshot.hpp.
- Rule or table: ARCH3-R146.

## Contributors: name order, contributors restored before the world, rollback

- Decision: contributors are sorted by name in the bytes and in the hash; a null entry or a repeated name is
  invalid_argument. Restore checks every recorded (name, version) against those offered
  (snapshot_contributor_unknown), backs the matched ones up, restores them in name order, then calls
  `world::restore_from`; any failure restores the backups and returns the failing code (a failed rollback is
  internal). An offered contributor the snapshot does not record is left unchanged.
- Why: the brief says world.restore_from then each contributor; restore_from cannot be undone once it succeeds, while a
  contributor can be restored from its own capture, so the reverse order makes "restores nothing" hold for a failing
  contributor too.
- Where: engine/runtime/src/snapshot_restore.cpp `match_contributors`, `roll_back`, `restore`,
  engine/runtime/src/snapshot_hash.cpp `sorted_contributors`.
- Rule or table: ARCH3-R144, R145.

## Input checks and code mapping

- Decision: take, restore, state_hash and breakdown return invalid_argument when the registry is not the world's, the
  type registry is not frozen, or a component's reflection is not the type registered under its name. restore_from's
  invalid_argument becomes snapshot_corrupt; archetype_limit and out_of_memory pass through.
- Why: the type digest is only meaningful against the frozen registry; an image the world refuses came from the bytes.
- Where: engine/runtime/src/snapshot_hash.cpp `check_inputs`, engine/runtime/src/snapshot_restore.cpp `restore`.
- Rule or table: ARCH3-R144, `error_codes`.

## runtime_abi_digest is the caller's

- Decision: the runtime_abi_digest and schedule digest come in `snapshot_meta` and restore's `expected_abi`; no
  function computes them yet. component_registry::layout_digest still hashes a placeholder field count (WO-088).
- Why: the digest's inputs (build, compiler, layout) are not defined in a landed header; layout_digest is outside
  WO-095's paths.
- Where: engine/runtime/include/sl/runtime/snapshot.hpp `snapshot_meta`, `restore`.
- Rule or table: ARCH3-R144.

## Test oracles and budgets

- Decision: RT-INV-SNAP-02 builds the restored world's oracle by replaying the prefix on a scratch world. The driver
  stream that seeds each tick is the snapshot's rng contributor. The ticks leave out gen_large (2 KiB values hashed four
  times a tick) and gen_tracked (not trivially copyable) and run 30 operations a tick, scaled by
  SL_RUNTIME_STRESS_SCALE. RT-INV-SNAP-03 uses a two-byte contributor so the whole snapshot stays under 1 KiB.
- Why: the world_gen oracle cannot be copied; the debug build must stay within the 60 s integration budget.
- Where: tests/integration/runtime/snap_continue_test.cpp, tests/unit/runtime/snap_bitflip_test.cpp.
- Rule or table: ARCH3-R014, R145.

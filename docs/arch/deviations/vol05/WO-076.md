# WO-076 deviations: runtime scaffold, error domain and failpoint registry

## to_string cases live in the core header, not in error.cpp

- Decision: the 54 `to_string(errc)` cases of the runtime codes are in engine/core/include/sl/core/error.hpp;
  engine/core/src/error.cpp is unchanged.
- Why: `sl::to_string(errc)` is a constexpr function defined in the header (static_asserts in tests use it); error.cpp
  holds only `describe()`. A case in the .cpp is impossible without moving the function.
- Where: engine/core/include/sl/core/error.hpp `sl::to_string(errc)`, `sl::domain`, `sl::to_string(error_domain)`.
- Rule or table: ARCH3-R017, `error_codes`.

## Area comments inside the runtime block

- Decision: under `// runtime 6000-6999 (SL-ARCH-003, ADR-0022)` each area of the table opens with a
  `// runtime <area>` line (general, lifecycle, platform, ...), mirroring the fabric block.
- Why: readability; no number or name changes.
- Where: engine/core/include/sl/core/error.hpp `sl::errc`.
- Rule or table: `error_codes`.

## is_runtime_code is false for reserved numbers

- Decision: `is_runtime_code(code)` is constexpr in the header and true only when `domain(code)` is runtime and the
  number is an enumerator (`to_string` is not "unknown"); 6007, 6113 and the other reserved numbers return false.
- Why: SL-ARCH-003 lists reserved ranges; a reserved number is not a code of the table (ARCH3-R018).
- Where: engine/runtime/include/sl/runtime/error.hpp `sl::runtime::is_runtime_code`.
- Rule or table: ARCH3-R017, ARCH3-R018, `error_codes` reserved.

## make_error has a const char * overload

- Decision: `sl::runtime::make_error(errc, std::string_view, source_location)` plus an overload taking
  `const char *`, both forwarding to `sl::make_error`.
- Why: inside sl::runtime an unqualified `make_error(errc::x, "text")` also finds `sl::make_error` by ADL on errc; with
  string_view alone both need a user conversion and the call is ambiguous. The exact const char * overload wins
  (proved by `refuse_start` in err_codes_test.cpp and by faults_arm.cpp).
- Where: engine/runtime/include/sl/runtime/error.hpp `sl::runtime::make_error`.
- Rule or table: not covered.

## Table types, versions and counts

- Decision: the row types are `error_code_info {name, number, area}` and `failpoint_info {id, name, site}`; the
  failpoint table has no outcome column. Added constants: `error_code_table_version = 1`,
  `failpoint_table_version = 1` (the `table_version` fields) and `failpoint_count = 11`.
- Why: the brief names the fields, not the type; the versions are inputs of runtime_abi_digest (ARCH3-R032) and the
  contract dump (WO-100); outcomes are prose verified by the stress matrix (RT-INV-STRESS-08), not code data.
- Where: engine/runtime/include/sl/runtime/error.hpp, faults.hpp; engine/runtime/src/error.cpp `error_codes`
  (a static_assert binds every row to its errc enumerator), src/faults.cpp `failpoints`.
- Rule or table: `error_codes`, `failpoints`, ARCH3-R032.

## How testing reaches the registry

- Decision: faults.hpp declares `detail::fault_registry_hooks` with private static `arm` and `disarm` and the friend
  `testing::fault_arming`, which is defined only in engine/runtime/testing/faults_arm.cpp (sl_runtime_testing). The
  hooks are defined in src/faults.cpp; with SL_RUNTIME_FAULTS=0 they are no-ops.
- Why: the registry must be in src/faults.cpp (ARCH3-R008) while arming must be possible only through
  sl::runtime::testing (ARCH3-R020); same pattern as the fabric's testing::tx_failpoints and backdoor.
- Where: engine/runtime/include/sl/runtime/faults.hpp `detail::fault_registry_hooks`;
  engine/runtime/testing/faults_arm.cpp `testing::fault_arming`.
- Rule or table: ARCH3-R008, ARCH3-R020.

## The registry is a function-local constinit static named fault_registry

- Decision: the registry is `static constinit std::array<fault_slot, 11> fault_registry{}` inside
  `registry()` in an anonymous namespace of src/faults.cpp, one 64-byte-aligned slot per failpoint (visits, target,
  param, sticky; all std::atomic). tools/runtime/lint_allow.json (WO-077) should allow-list path
  engine/runtime/src/faults.cpp, rule R-RT-GLOBAL, symbol `fault_registry`.
- Why: a namespace-scope mutable object fails clang-tidy cppcoreguidelines-avoid-non-const-global-variables (a gate
  of `just tidy`); a function-local constinit object is constant-initialized (no guard, no init order) and passes
  without NOLINT. It is still the one mutable state of the runtime.
- Where: engine/runtime/src/faults.cpp `registry()`, `fault_registry`.
- Rule or table: ARCH3-R008.

## Arming semantics

- Decision: `arm(point, at_visit, sticky, param)` fires at the at_visit-th visit counted from the arm() call (not
  from process start), once, or at that visit and every later one when sticky; `param` is returned only by a firing
  visit. Re-arming replaces the previous arming. Errors: unsupported when compiled out (checked first),
  invalid_argument for at_visit 0 or a value outside rfp0..rfp10. `visits()` counts since process start and is never
  reset (tests use deltas). A visit of an out-of-range value proceeds and is not counted.
- Why: the table says "Nth call" without an origin; counting from the arm call makes a test independent of earlier
  visits in the same process. Non-sticky firing needs no extra flag: each visit gets a unique number by fetch_add.
- Where: engine/runtime/src/faults.cpp `visit`, `visits`, `detail::fault_registry_hooks::arm`;
  engine/runtime/testing/faults_arm.cpp `testing::arm`.
- Rule or table: ARCH3-R020, `failpoints`.

## testing::disarm(failpoint) and scoped_arm::status()

- Decision: besides `disarm_all()` there is `disarm(failpoint)`; `scoped_arm` stores the arm() result
  (`status()`) and disarms only its own point, only when arming succeeded.
- Why: a constructor cannot return result<void>; a scope must not disarm points another scope armed.
- Where: engine/runtime/testing/faults_arm.hpp `testing::disarm`, `testing::scoped_arm`.
- Rule or table: ARCH3-R020.

## Memory orders of the registry

- Decision: visit counts use relaxed fetch_add; `target` is stored with release after `param` and `sticky` (relaxed)
  and loaded with acquire; arm stores target 0 first. Every explicit order carries a `// pairs:` comment.
- Why: lock-free counting; arming is owner-thread before the workload (`thread_safety`, testing::*). TSan-clean
  (`just runtime-san tsan flt`, 8 threads).
- Where: engine/runtime/src/faults.cpp.
- Rule or table: R-RT-ORDER (WO-077), ARCH3-R175.

## SL_RUNTIME_FAULTS is always defined

- Decision: CMake defines SL_RUNTIME_FAULTS=1 when SL_SANITIZE is set, else `$<IF:$<CONFIG:Debug>,1,0>`;
  faults.hpp defines it 0 when a stray translation unit lacks it. `faults_compiled = SL_RUNTIME_FAULTS != 0`.
- Why: -Wundef is on; the fabric block defines its macro only when on, which would not work with `#if`.
- Where: engine/runtime/CMakeLists.txt; engine/runtime/include/sl/runtime/faults.hpp.
- Rule or table: ARCH3-R020.

## Build layout details

- Decision: sl_runtime_all_tests is created by whichever tier directory comes first (`if(NOT TARGET)`) and also
  depends on sl_runtime and sl_runtime_testing; the rt_* executables generate their doctest main like SlTesting and
  register through `_sl_test_finish`; sl_runtime_testing has no include directory (tests include
  engine/runtime/testing/*.hpp by relative path, as the fabric tests do); runtime tools get sl_target but not
  sl_provenance (as the fabric tools); sl_runtime_demo links sl_runtime_demo_scene when that target exists.
- Why: the brief leaves these open; the choices mirror engine/fabric and tests/unit/fabric.
- Where: tests/unit/runtime/CMakeLists.txt, tests/integration/runtime/CMakeLists.txt,
  engine/runtime/testing/CMakeLists.txt, engine/runtime/tools/CMakeLists.txt.
- Rule or table: ARCH3-R001, ARCH3-R016.

## Script details

- Decision: runtime-san runs ctest with -V so a report inside a passing test still reaches the log; the log is
  build/runtime/san/<san>-all.log when no area is given. runtime-gcc adds one build target per
  engine/runtime/tools/sl_*.cpp. runtime-tidy builds sl_runtime_all_tests, passes each file to run-clang-tidy as an
  anchored, dot-escaped absolute-path regex, treats a table entry without .cpp as a prefix glob, and exits 1 when an
  area has no existing file at all.
- Why: fail-closed (tidy over nothing proves nothing); run-clang-tidy takes regexes on the compile-database path.
- Where: scripts/runtime/runtime-san.sh, runtime-gcc.sh, runtime-tidy.sh.
- Rule or table: ARCH3-R015, ARCH3-R016.

## ERR-03 golden also forbids new numbers below 6000

- Decision: err_stability_test.cpp holds the 82 pre-Volume-05 enumerators (ok included) and scans 0-5999, so a new
  enumerator below 6000 fails it as well as a renumbering.
- Why: "equals the committed list" read both ways; a new core code needs its own order and ADR anyway.
- Where: tests/unit/runtime/err_stability_test.cpp.
- Rule or table: ARCH3-R017, RT-INV-ERR-03.

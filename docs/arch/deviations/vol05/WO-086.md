# WO-086 deviations: work stealing (episode 088)

## make_ws_queue capacity: rounded up to a power of two, capped at 65536

- Decision: `make_ws_queue(capacity)` builds a ws_deque whose largest ring is min(bit_ceil(capacity), 65536) cells
  and whose first ring is min(4096, that); `capacity()` reports the largest ring. A capacity above 65536 (the job
  system asks for job_config::capacity, up to 2^24) gets 65536: push returns false at the maximum and the job system
  queues the job on its frame injection queue. Capacity 0 is invalid_argument.
- Why: the queue factory passes one number; the `limits` table fixes the ring at 4096 doubling to 65536, and the
  contract suite needs a queue no larger than asked to fill to capacity() quickly.
- Where: engine/runtime/src/queue_ws.cpp `ws_deque::create`, `make_ws_queue`.
- Rule or table: ARCH3-R072, `limits` ws_deque_initial_cells, ws_deque_max_cells.

## ws_deque API beyond work_queue

- Decision: ws_deque.hpp adds `ws_deque::create(capacity)` (the deque is built only through it: the first ring
  allocation can fail), the constants `ws_deque_initial_cells` and `ws_deque_max_cells`, and two observers for tests:
  `cells()` (current ring, any thread) and `retired_rings()` (owner or quiescent).
- Why: a constructor cannot report out_of_memory without throwing; RT-INV-STEAL-02 and -03 must see growth and the
  quiesce free.
- Where: engine/runtime/include/sl/runtime/ws_deque.hpp `ws_deque`.
- Rule or table: ARCH3-R072, ARCH3-R174.

## The owner worker is the first thread that pushes or pops

- Decision: ws_deque records the first thread that calls push or pop (a compare-exchange on a std::thread::id) and
  SL_DEBUG_ASSERTs that every later push or pop comes from it. Release builds do not evaluate the check.
- Why: the job system builds each local queue on its owner thread and only the worker uses it; work_queue has no
  call that names the owner.
- Where: engine/runtime/src/queue_ws.cpp `ws_deque::owned_by_caller`.
- Rule or table: ARCH3-R175, `thread_safety` ws_deque push/pop, Debug assertions table.

## Retired rings: an in-object array, freed at quiesce only with no thief reading

- Decision: rings live in a fixed array of 17 slots inside the deque (1 to 65536 cells by doubling), so retiring a
  ring allocates nothing. A thief that found the deque non-empty increments `readers_` before it loads `ring_` and
  decrements it after reading the cell; `quiesce()` frees the retired rings only when `readers_` is 0 (seq_cst) and
  otherwise leaves them for the next quiesce.
- Why: job_system::quiesce runs with no job in flight, but idle workers keep calling steal; a thief preempted between
  its ring load and its cell read would otherwise read freed memory. A thief that increments after quiesce read 0
  loads the current ring (seq_cst order), which is never freed.
- Where: engine/runtime/src/queue_ws.cpp `ws_deque::steal`, `ws_deque::quiesce`, `ws_deque::grow`.
- Rule or table: ARCH3-R072.

## Memory orders: seq_cst everywhere but the two of push

- Decision: only the cell store (relaxed) and the bottom_ store (release) of push are weaker than seq_cst; the owner's
  own loads of bottom_, the empty-restore stores of pop, ring publication and every cell load are seq_cst.
- Why: ARCH3-R072 names the push orders and seq_cst for pop and steal; the remaining operations are left open, and
  seq_cst needs no `// pairs:` argument and is what ThreadSanitizer models best.
- Where: engine/runtime/src/queue_ws.cpp `ws_deque::push`, `pop`, `steal`, `grow`.
- Rule or table: ARCH3-R058, ARCH3-R072, ADR-0024.

## Steal seed: steal_options::seed mixed with the job system seed

- Decision: slot i's xorshift64 state is splitmix64((steal_options::seed ^ seed passed to on_start) ^ i), replaced by
  the splitmix constant if it is 0.
- Why: job_system::start passes job_config::seed to on_start; mixing both keeps one knob per layer and leaves the
  sequence identical for the same pair (job_config::seed defaults to 0).
- Where: engine/runtime/src/policy_steal.cpp `steal_policy::on_start`.
- Rule or table: ARCH3-R074.

## Victim draws: one per attempt, an owner slot, attempts past 2 x workers skipped

- Decision: the policy has one slot per worker plus the job system's owner thread at index `workers` (the owner also
  steals). Each `victim` call draws one xorshift64 value: a worker gets a uniform other worker, the owner slot any
  worker, a lone worker itself (skip). An attempt index of 2 x workers or more returns self (skip).
- Why: the job system calls victim(self, attempt) for attempt 0 to 2 x workers - 1 from the owner too; the skip keeps
  the per-round bound in the policy as well.
- Where: engine/runtime/src/policy_steal.cpp `steal_policy::victim`.
- Rule or table: ARCH3-R074, `limits` steal_attempts_per_round.

## Injection poll: once per multiple of 61

- Decision: `poll_injection(self, local_pops)` is true when local_pops is a non-zero multiple of injection_poll_every
  and differs from the count of the slot's previous true answer.
- Why: the job system does not advance local_pops when the injection poll returned a job, so a plain modulo would
  poll the injection queue first on every round and starve the local queue.
- Where: engine/runtime/src/policy_steal.cpp `steal_policy::poll_injection`.
- Rule or table: ARCH3-R074, `limits` injection_poll_every.

## Background promotion and its counter

- Decision: `promote_background(waited)` is true for waited >= aging_limit; an aging promotion is counted once per
  crossing (waited == aging_limit) on the slot whose recorded thread id is the caller's (the owner slot when none
  matches). The job system's own floor (every aging_limit-th round, WO-082) stays.
- Why: "after aging_limit rounds" and "starts within aging_limit rounds" both hold at >=; the seam's
  promote_background is const and has no worker index, and true does not mean a job was taken, so counting every
  true answer would count idle rounds.
- Where: engine/runtime/src/policy_steal.cpp `steal_policy::promote_background`, `caller_slot`, `note_thread`.
- Rule or table: ARCH3-R075, ARCH3-R076.

## jobs_run reads 0 from the stealing policy

- Decision: `worker_counters::jobs_run` is 0 in the stealing policy's counters. RT-INV-STEAL-05 binds "counters sum to
  the jobs run" with per-thread job counts taken in the job bodies (sum = jobs run = stats().completed), successful
  steals <= jobs run, and scheduler_stats::total() equal to the field-wise sum of the slots.
- Why: the scheduler_policy seam (WO-082) has no hook when a job runs, and job_system*.cpp is a non-goal. Open issue:
  WO-096 (or a job system change) adds an on_run hook or fills jobs_run in the job system.
- Where: engine/runtime/src/policy_steal.cpp `steal_policy::read_counters`; tests/unit/runtime/steal_equiv_test.cpp.
- Rule or table: ARCH3-R076, RT-INV-STEAL-05.

## collect takes the policy handed to the job system; slot count is the caller's

- Decision: `collect(policy, n)` reads slots [0, n); the caller keeps a pointer to the policy before moving it into
  job_config::policy and passes worker_count() + 1 to include the owner slot. collect is not noexcept (it allocates
  the vector), like drain_results.
- Why: job_system has no policy accessor and job_system*.cpp is a non-goal.
- Where: engine/runtime/include/sl/runtime/scheduler_stats.hpp `collect`; src/policy_steal_stats.cpp.
- Rule or table: ARCH3-R076, `thread_safety` scheduler_stats read.

## make_steal_policy validation

- Decision: injection_poll_every 0 or aging_limit 0 is invalid_argument; spin_limit 0 is accepted (park at once).
- Why: a zero modulus is undefined and aging 0 would promote every round; the defaults are the `limits` values.
- Where: engine/runtime/src/policy_steal.cpp `make_steal_policy`.
- Rule or table: ARCH3-R174, `limits` injection_poll_every, aging_limit, spin_limit.

## The default queue stays locked_deque

- Decision: job_config::make_queue still defaults to make_locked_queue and the reference policy stays the default;
  ws_deque and make_steal_policy are opt-in through job_config.
- Why: the brief moves the default in WO-096, and only if `just runtime-san tsan steal` is green here.
- Where: engine/runtime/include/sl/runtime/jobs.hpp (unchanged).
- Rule or table: ARCH3-R073, ADR-0024.

## Stale statements outside paths_allowed

- Decision: not changed here. work_queue.hpp still says make_ws_queue "returns unsupported until WO-086", and
  tests/unit/runtime/job_dag_test.cpp case "RT-INV-JOB-01: make_ws_queue is unsupported until WO-086 and start fails
  with it" asserts `make_ws_queue(16).error().code == unsupported`, which no longer holds (calling error() on a value
  is undefined). That case must become: make_ws_queue(16) succeeds with capacity() 16 and job_system::start succeeds
  with make_queue = make_ws_queue (the reference-policy checks of the case stay).
- Why: both files are outside paths_allowed; WO-082 wrote them for the stub this order replaces.
- Where: engine/runtime/include/sl/runtime/work_queue.hpp `make_ws_queue`; tests/unit/runtime/job_dag_test.cpp.
- Rule or table: ARCH3-R070, ARCH3-R013.

## Test design

- Decision: RT-INV-STEAL-03 floors its burst at 3 x 4096 pushes and throttles its 3 thieves to half the pushed count
  so the ring must grow while they steal (a second run uses 7 free thieves). RT-INV-STEAL-04 measures "rounds" as the
  worker's jobs run between the submit and the start (one job per round while saturated). RT-INV-STEAL-06 waits each
  round until every worker parked again since the previous submit, with 5 s bounds instead of hangs.
- Why: growth and park timing are otherwise nondeterministic; rounds are not observable outside the job system.
- Where: tests/integration/runtime/steal_growth_test.cpp, steal_park_test.cpp; tests/unit/runtime/steal_fairness_test.cpp.
- Rule or table: RT-INV-STEAL-03, -04, -06, ARCH3-R016.

## NOLINT for bounded indices and the nothrow rings

- Decision: `cppcoreguidelines-pro-bounds-constant-array-index` is suppressed around steal_policy (every index is
  checked against workers_ <= 64 or bounded by the 65 slots) and on the two rings_ subscripts; `avoid-c-arrays` on
  the `unique_ptr<std::atomic<std::uint32_t>[]>` cells.
- Why: the indices are checked against fixed bounds; a std::vector ring would throw on allocation failure.
- Where: engine/runtime/src/policy_steal.cpp, queue_ws.cpp; engine/runtime/include/sl/runtime/ws_deque.hpp.
- Rule or table: not covered.

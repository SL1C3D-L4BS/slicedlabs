# WO-078 deviations: the platform boundary (episode 082)

Builder record for platform.hpp, headless_platform.hpp, src/platform_*.cpp, testing/scripted_platform.* and the six
plat_*_test.cpp files. SL-ARCH-003 was not edited.

## thread_group carries the reverse release order

- Decision: platform.hpp adds `thread_group` (move-only; `spawn(factory, name, body, hint)`, `size()`, `release()`
  joining the newest handle first and returning the names in release order; the destructor releases).
- Why: ARCH3-R037 asks for release in reverse acquisition order, and a bare `thread_handle` cannot express or prove an
  order (a std::vector destroys front to back). The job system (WO-081) can own its workers through it.
- Where: engine/runtime/include/sl/runtime/platform.hpp `thread_group`; src/platform_threads.cpp.
- Rule or table: ARCH3-R037, RT-INV-PLAT-04.

## The factory names threads, the caller passes the suffix

- Decision: `spawn(name, ...)` names the thread `slrt<instance>-<name>`; callers pass `w<k>`. `thread_handle::name()`
  is the full name, the OS name (pthread_setname_np, set by the new thread before the body runs) its first 15 bytes.
  An empty name or empty body is invalid_argument; RFP1 is visited before that check.
- Why: the brief gives spawn a name parameter and ARCH3-R040 makes the factory responsible for the prefix; only the
  caller knows k.
- Where: src/platform_threads.cpp `os_thread_factory::spawn`, `thread_main`.
- Rule or table: ARCH3-R040, `error_codes` (invalid_argument is a reused core code, ARCH3-R018).

## pthread_create instead of std::thread

- Decision: threads are created with pthread_create; `thread_handle` is a pimpl over pthread_t, so the public header
  names no std::thread; a pthread_create error is thread_spawn_failed with the error number in the message.
- Why: the std::thread constructor reports failure by throwing std::system_error, which a noexcept spawn would turn
  into std::terminate (no try/catch in the runtime, R-RT-THROW).
- Where: platform.hpp `thread_handle`; src/platform_threads.cpp `thread_handle::state`, `start_block`.
- Rule or table: ARCH3-R010, ARCH3-R035.

## Interfaces share platform_interface; concrete headless types are public

- Decision: the six interfaces derive from `platform_interface` (deleted copy and move, virtual destructor). The
  headless implementations `steady_clock_source`, `system_wall_clock`, `os_thread_factory`, `null_input_source` and
  `headless_window` are declared in headless_platform.hpp.
- Why: one rule-of-five block instead of six; paths_allowed has no private src header, headless_platform owns these
  members by value, and testing's failing_thread_factory delegates to os_thread_factory.
- Where: platform.hpp `platform_interface`; headless_platform.hpp.
- Rule or table: ARCH3-R036, `layers` (both headers L1).

## file_access paths, root and construction

- Decision: paths are `std::string_view`; a relative path resolves against `root()`, a path starting with '/' is used
  as given. `file_access(vfs&, root)` borrows a vfs; `file_access::make_posix(root)` owns a vfs_posix and creates root
  and its parents (make_dir per component, already_exists accepted). Move-only; a moved-from object returns io_error.
  atomic_write writes `<path>.tmp`, fsyncs, closes, renames, then sync_dir of the parent ("." when none); the directory
  must exist; after a failure it tries to remove the temp file (best effort); a sync_dir failure after the rename is
  io_error. remove of a missing file is not_found.
- Why: the brief names the operations, not the path type or how the POSIX vfs is reached; vfs.hpp may be included
  only by platform_files.cpp, so the owning constructor lives there.
- Where: platform.hpp `file_access`; src/platform_files.cpp `make_posix`, `resolve`, `atomic_write`, `fail`.
- Rule or table: ARCH3-R038, R-RT-FABRIC.

## vfs error mapping

- Decision: a vfs not_found stays not_found; every other vfs code (store_io, already_exists, writer_locked,
  decode_truncated, unsupported, ...) becomes io_error with the primitive, the path and the vfs message.
  make_headless_platform turns any make_posix error into platform_unavailable.
- Why: ARCH3-R018 allows only the listed core codes; the brief says "vfs errors map to io_error, not_found".
- Where: src/platform_files.cpp `fail`; src/platform_headless.cpp `make_headless_platform`.
- Rule or table: ARCH3-R018, `error_codes` platform_unavailable.

## window has headless, width and height only

- Decision: `window` is headless(), width(), height(); no call needs a display in Volume 05, so none returns
  platform_unavailable yet.
- Why: the brief elides the rest ("..."); ADR-0006 and the non-goals forbid window code.
- Where: platform.hpp `window`; headless_platform.hpp `headless_window`.
- Rule or table: ARCH3-R036, `error_codes` platform_unavailable ("window calls that need a display").

## Recording helpers and the file digest

- Decision: platform.hpp adds `record_wall_sample(clock, sink, frame)`, `record_input(input, sink, frame, tick,
  buffer)`, `record_file_read(files, sink, frame, tick, path)` and `content_digest(bytes)`; the digest a file read
  records is a `sl::fabric::digest` with algo sha256 over the raw bytes (not hash_object, which frames them). A failed
  read records nothing. on_wall_sample carries no tick (the brief's signature). `null_record_sink` has no overrides;
  the defaults are defined in src/platform_record.cpp.
- Why: ARCH3-R039 needs one place that passes each input once in arrival order; WO-089 calls these in begin_frame.
- Where: platform.hpp; src/platform_record.cpp.
- Rule or table: ARCH3-R039, seams V06-4 and V17-5.

## Constants outside the limits table

- Decision: `input_payload_bytes = 48` (the brief's payload size) and the 15-byte OS thread name (a Linux limit) are
  constants in code; neither is in `limits`.
- Why: ARCH3-R174 wants every size from the table; the brief fixed 48, Linux fixes 15. WO-100 may add both rows.
- Where: platform.hpp `input_payload_bytes`; src/platform_threads.cpp `os_name_bytes`.
- Rule or table: ARCH3-R174, `limits`.

## platform holds references under a scoped NOLINT

- Decision: `struct platform` keeps the brief's reference members inside NOLINTBEGIN/END
  (cppcoreguidelines-avoid-const-or-ref-data-members) with a one-line reason.
- Why: the brief fixes the shape; the platform is a view of objects the host owns.
- Where: platform.hpp `platform`.
- Rule or table: `ownership` (platform: host, outlives the runtime).

## headless_platform details

- Decision: the constructor `headless_platform(options, file_access)` is public (make_unique); members are destroyed
  in reverse declaration order; the sink is a null_record_sink, so a recording host builds its own `platform` view
  from get() with its sink.
- Why: the brief gives only the factory function and get().
- Where: headless_platform.hpp `headless_platform`; src/platform_headless.cpp.
- Rule or table: ARCH3-R036, ARCH3-R037.

## scripted_platform surface

- Decision: besides manual_clock, scripted_input and failing_thread_factory it has `manual_wall_clock`,
  `recording_sink` (records `record {kind, frame, tick, code, sample, path, data}`, `serialize()` to little-endian
  bytes), `scripted_input::pending()`, and accessors wall(), input(), threads(), vfs() (the faulty_vfs over a
  vfs_memory), files() (root "/") and sink(). `fail_at(k)` fails the k-th spawn counted from the call (0 disarms) and
  does not visit RFP1; `arm_rfp1(k, sticky)` is testing::arm(rfp1, ...). manual_clock uses seq_cst atomics (no
  explicit order). scripted_platform.hpp includes ../../fabric/testing/faulty_vfs.hpp by relative path.
- Why: PLAT-02 needs a byte-comparable log and PLAT-06 needs fault control; the brief ends with "...".
- Where: engine/runtime/testing/scripted_platform.hpp, scripted_platform.cpp.
- Rule or table: ARCH3-R036, ARCH3-R020 (arming only through testing).

## atomic_write does not visit RFP8

- Decision: file_access::atomic_write visits no failpoint; PLAT-06 crashes it at each primitive through the faulty
  vfs (fail_after(k), then crash with drop_unsynced and keep_unsynced).
- Why: the `failpoints` site of RFP8 is snapshot::save (WO-095), which wraps atomic_write.
- Where: src/platform_files.cpp `atomic_write`; tests/unit/runtime/plat_files_test.cpp.
- Rule or table: `failpoints` RFP8, ARCH3-R038.

## The RFP1 branch is compiled only with SL_RUNTIME_FAULTS

- Decision: the RFP1 visit and its thread_spawn_failed return in spawn are inside `#if SL_RUNTIME_FAULTS`; Debug and
  sanitizer builds behave as before, Release has no visit at all.
- Why: with the failpoints compiled out visit() is a constexpr no-op that never fires, so the return after it is
  unreachable and ci-release fails with -Wunreachable-code-return (WO-079 did the same in memory_tracking.cpp).
- Where: src/platform_threads.cpp `os_thread_factory::spawn`.
- Rule or table: ARCH3-R020, `failpoints` RFP1.

## arm_rfp1 is static; the testing files need the full tidy

- Decision: `failing_thread_factory::arm_rfp1(k, sticky)` is a static member (it arms the process-wide RFP1 and
  touches no member). The area table of `just runtime-tidy plat` (`platform_*`) does not cover
  engine/runtime/testing/scripted_platform.cpp; that file is checked only by `just tidy` (full tree) or by
  run-clang-tidy on it by hand.
- Why: `just tidy` reported readability-convert-member-functions-to-static there; scripts/runtime/runtime-tidy.sh is
  outside paths_allowed, so WO-100 may add testing/scripted_platform.cpp to the plat row.
- Where: engine/runtime/testing/scripted_platform.hpp `failing_thread_factory::arm_rfp1`;
  scripts/runtime/runtime-tidy.sh `sources[plat]`.
- Rule or table: ARCH3-R015, ARCH3-R016.

## How the invariants are exercised before the runtime exists

- Decision: PLAT-01's start, 100 frames and stop are a worker spawned through the platform, 100 frames of one wall
  sample and one input poll each, then release; PLAT-05 drives frames and ticks by hand; PLAT-04's "no thread left"
  is the /proc/self/task count once stable (20 equal reads 1 ms apart); PLAT-03 reads SL_RUNTIME_STRESS_SCALE itself
  (floor 1) and also checks each sample against the newest one another thread published.
- Why: runtime::start (WO-096) and the frame scheduler (WO-089) come later; an exiting thread can stay listed for a
  moment after its join returns.
- Where: tests/unit/runtime/plat_headless_test.cpp, plat_record_test.cpp, plat_thread_test.cpp, plat_clock_test.cpp.
- Rule or table: invariants RT-INV-PLAT-01, 03, 04, 05.

## file_access thread safety: per path, not per handle

- Decision: file_access holds no mutable state of its own and relies on the vfs being thread-safe; concurrent calls on
  different paths are allowed, one call per path at a time (the brief). The `thread_safety` row says "one call per
  handle at a time"; file_access exposes no handle.
- Why: the brief and the table use different words for the same restriction.
- Where: platform.hpp `file_access`.
- Rule or table: ARCH3-R175, `thread_safety` (platform file_access::*).

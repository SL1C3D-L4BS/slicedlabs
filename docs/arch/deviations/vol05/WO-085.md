# WO-085 deviations: allocation diagnostics (episode 085)

Builder record for memdiag.hpp, src/memdiag_{report,json,events}.cpp, tools/runtime/memreport_check.py and its test,
the five diag_*_test.cpp files and the neg-runtime-leak gate. SL-ARCH-003 was not edited.

## report_external returns result<void>

- Decision: `[[nodiscard]] result<void> report_external(memory_tag, std::uint64_t) noexcept` instead of `void`:
  invalid_argument for a tag that is not registered or not registered through reserve_external (untagged included).
  The bytes are a relaxed store that replaces the previous value (sets, not adds).
- Why: the brief asks for invalid_argument on a non-external tag, and every fallible call returns sl::result (ADR-0009);
  a void function cannot report it.
- Where: memdiag.hpp `diagnostics::report_external`; src/memdiag_report.cpp.
- Rule or table: ARCH3-R056, ADR-0009, `thread_safety` (any-thread).

## Allocator free space is sampled on the owner thread

- Decision: make_report never calls free_space_stats. add(name, resource) samples it at once and on_frame_end samples
  every source again (owner thread, end_frame slot diagnostics) into relaxed atomics; make_report reads the samples.
  An owner-thread pool can therefore be added unwrapped; a synchronized_resource works too (its mutex is taken only
  by the owner thread's sample, never by a report).
- Why: the brief makes make_report any-thread with relaxed loads only, and WO-081 left open that free_space_stats of
  an unwrapped pool asserts the owner (and is not atomic). Reading it from a reader thread would race or block
  allocation (ARCH3-R055).
- Where: src/memdiag_report.cpp `diagnostics::sample_allocators`, `diagnostics::add`, `make_report`;
  src/memdiag_events.cpp `on_frame_end`.
- Rule or table: ARCH3-R052, ARCH3-R055, `thread_safety`; resolves the open item of WO-081.md.

## What a report lists and how counters combine

- Decision: tags: every registered non-external tag (zeros included) plus `untagged` when it has counters, sorted by
  name; counters are summed over every tracking_resource added (a summed peak is the sum of per-resource peaks, an
  upper bound); ids a tracking resource uses beyond the registry are not reported. A block a tracking resource holds
  under an external tag is not reported as tracked bytes (it still appears in leaks()). external: every tag
  registered through reserve_external, sorted by name, 0 until reported. allocators: sorted by name. leaks: empty
  (see below).
- Why: the brief fixes the fields but not the row set; listing every registered tag keeps reports of one runtime the
  same shape every frame; ARCH3-R056 keeps external bytes out of tracked live bytes.
- Where: src/memdiag_report.cpp `diagnostics::make_report`.
- Rule or table: ARCH3-R052, ARCH3-R056, RT-INV-DIAG-01.

## Self-consistent and monotone reports under concurrency

- Decision: a report shows allocs as max(allocs, frees) and peak as max(peak, live, every peak an earlier report
  showed for that tag) through a relaxed CAS max in a mutable per-tag array (`peak_seen_`). Quiescent reports are
  unchanged by this.
- Why: tracking_resource updates live before the peak CAS and its relaxed counters can be read out of order, so a raw
  read can show live > peak or frees > allocs and a later raw read a lower peak; the checker requires live <= peak and
  frees <= allocs, and RT-INV-DIAG-04 requires monotone totals. A relaxed RMW does not block allocation.
- Where: src/memdiag_report.cpp `raise_to`, `diagnostics::make_report`; memdiag.hpp `diagnostics::peak_seen_`.
- Rule or table: ARCH3-R055, RT-INV-DIAG-04.

## Leaks: shutdown only, and the Release form

- Decision: make_report leaves leaks empty; leaks() (owner thread, shutdown) gives one entry per live block of every
  tracking resource, tag named by the diagnostics' registry, site "<file>:<line>" (the std::source_location file as
  compiled, i.e. an absolute path under CMake), sorted by (tag, site, size). Release keeps no site table: one entry
  per tag with live blocks, site "unknown", size its live bytes. The shutdown report is make_report(frame) with
  `leaks = leaks()` (WO-096).
- Why: tracking_resource::leaks takes the site-table mutex that allocation takes, so a report that read it would block
  allocation (ARCH3-R055); Release has no sites (WO-079.md) and the schema needs a non-empty site and size >= 1.
- Where: src/memdiag_report.cpp `diagnostics::leaks`.
- Rule or table: ARCH3-R054, ARCH3-R027, RT-INV-DIAG-03.

## upstream_allocs_last_frame

- Decision: the tracked allocations (sum of totals().allocs over the tracking resources) made between the previous
  on_frame_end (or add) and this one, stored as a relaxed atomic.
- Why: the brief names the field but not its source; the tracking resources are the runtime's only upstream (global
  operator new is not replaced, ARCH3-R047), so a steady frame shows 0 (gate_evidence memreport.json holds "steady
  upstream allocations per frame 0", ARCH3-R051).
- Where: src/memdiag_events.cpp `diagnostics::on_frame_end`; src/memdiag_report.cpp `diagnostics::add`.
- Rule or table: ARCH3-R051, `gate_evidence` memreport.json.

## The runtime.mem event: when, and its fields

- Decision: on_frame_end(frame) emits when frame != 0 and frame % report_interval == 0; report_interval 0 means 600
  (report_interval_frames). One info event, system runtime.mem, message "memory report", under
  `sl::log::correlation_scope("runtime/<instance>", tick = frame)` (a fresh correlation id each time), fields
  instance, frame, live_bytes, live_blocks, peak_bytes, external_bytes, upstream_allocs_last_frame (totals), `tags`
  ("<tag>=<live>/<peak>" joined by "," in tag order) and `external` ("<tag>=<bytes>" joined by ",").
- Why: sl::log::emit takes a fixed initializer_list of fields, and the only other path (logger::log with a hand-built
  event) needs a timestamp, i.e. system_clock::now(), which R-RT-PLATFORM bans outside src/platform_*.cpp. One string
  field per list keeps "per tag live/peak" in one event.
- Where: src/memdiag_events.cpp `diagnostics::on_frame_end`.
- Rule or table: ARCH3-R053, `limits` report_interval_frames, RT-INV-DIAG-05.

## The event at shutdown is not emitted here

- Decision: diagnostics has no shutdown emission; ARCH3-R053's "and at shutdown" event is left to WO-096 (runtime
  shutdown), which owns the order of flush and leak report.
- Why: the brief lists no member for it (on_frame_end emits on the interval only) and the brief decides every name.
  Open for WO-096: either call on_frame_end with a multiple of the interval or add a flush member to memdiag.hpp.
- Where: memdiag.hpp `diagnostics`.
- Rule or table: ARCH3-R053, ARCH3-R027.

## Thread classes of the members the table does not list

- Decision: add (both overloads) and on_frame_end are owner-thread and not checked at run time; add must happen before
  any other thread reads reports (the source lists are plain vectors). leaks() is owner-thread (table row "leak report
  at shutdown"). The constructor SL_DEBUG_ASSERTs instance != 0 (the schema's minimum is 1).
- Why: `thread_safety` lists only make_report, report_external, to_json, from_json and the shutdown leak report.
- Where: memdiag.hpp `diagnostics`.
- Rule or table: ARCH3-R175, `thread_safety`.

## JSON layout and from_json strictness

- Decision: to_json writes the layout of schemas/runtime/examples/memreport.json (two-space indent, `"key": value`,
  empty arrays as `[]`, one trailing newline; strings escaped by sl::log::append_json_string) from sorted copies of
  all four arrays, so the example reads back to its exact bytes. from_json is a strict RFC 8259 parser (depth 16) that
  accepts any key order and whitespace, and rejects with invalid_argument and the key's JSON pointer: a missing,
  unknown or duplicate key, a non-string or empty name/tag/site, a non-integer, negative or > 2^64-1 number, the
  schema's ranges (instance 1..2^32-1, fragmentation_permille 0..1000, leak size >= 1) and another format; malformed
  JSON names its byte offset. Tag name patterns are left to the checker. fragmentation_permille is a public constexpr
  function; a run larger than the free bytes gives 0 and huge values are halved together until 1000 x run fits.
- Why: the brief fixes key order, integers and sorting but not the whitespace or how far from_json validates.
- Where: src/memdiag_json.cpp `to_json`, `from_json`, `parser`, `mapper`; memdiag.hpp `fragmentation_permille`.
- Rule or table: ARCH3-R052, ARCH3-R053, RT-INV-DIAG-02.

## memreport_check details

- Decision: findings print as `memreport-check: <file>: <json pointer>: <message>`; tags must be strictly increasing
  by name (a duplicate is an error), leaks non-decreasing by (tag, site, size); --no-leaks reports each leak as
  "leak of <size> bytes, tag <tag>, site <site>"; an unknown option is exit 2. main(argv, root, out) takes a root so
  the tests run it in-process on a temp tree. The neg gate also checks that the planted report stays schema-valid
  without --no-leaks, so the exit 1 it expects can only come from the leak.
- Why: the brief gives the checks, not the output format; no subprocess in tools tests.
- Where: tools/runtime/memreport_check.py; tools/runtime/test_memreport_check.py; tests/gates/neg_runtime_leak.sh.
- Rule or table: ARCH3-R053, RT-INV-DIAG-06.

## Test evidence files

- Decision: diag_json_test writes SL_RUNTIME_EVIDENCE_ROOT/test/memreport.json from a live diagnostics (the runtime
  tags, fabric.projection reported, a pool over a tracking root added as allocator); the pool's slab is still a live
  tracked block when the report is taken, the leak list is empty. diag_log_event_test writes its json_sink output to
  SL_RUNTIME_EVIDENCE_ROOT/work/diag_log_event.jsonl and deletes it (std::tmpfile needs /tmp, which the sandbox
  refuses).
- Why: runtime-memreport-check and neg-runtime-leak read the test report; tests write only under build/.
- Where: tests/unit/runtime/diag_json_test.cpp, diag_log_event_test.cpp.
- Rule or table: ARCH3-R016, `gate_evidence`.

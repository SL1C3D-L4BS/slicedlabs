# WO-092 deviations: typed runtime events (episode 097)

Builder record for events.hpp, src/event_registry.cpp, event_channel.cpp, event_export.cpp, event_contributor.cpp and
the seven evt_* test files. SL-ARCH-003 was not edited.

## writer_key and local_seq

- Decision: `writer_key` is {tick, ph (phase), system_index u16, chunk_index u32}: the ordered_key without its
  local_seq. The channel assigns local_seq per writer as the count of events that writer buffered since the last
  boundary (0..). One job writes under one key at a time; two jobs sharing a key would interleave local_seq.
- Why: the brief names `write(const writer_key &, ...)` but never defines writer_key; a job knows its tick, phase,
  system and chunk, and only the channel can count its writes without a second counter per job.
- Where: engine/runtime/include/sl/runtime/events.hpp `writer_key`, `detail::channel_core::push`.
- Rule or table: ARCH3-R086, `determinism` ordered_key.

## Writer buffers live in the channel under a mutex

- Decision: each channel keeps one `det::ordered_buffer` per (phase, system_index, chunk_index) in a `std::map`
  guarded by a `std::mutex`; write and try_write lock it. Buffers are cleared at each boundary, never erased, so a
  steady frame allocates no map node; the tick is part of each entry's key, not of the map key.
- Why: write is worker-only and called concurrently by many jobs; there is no per-job storage API yet (systems are
  WO-094) and a lock is TSan-clean and deterministic because order comes from the keys, not from arrival.
- Where: events.hpp `detail::channel_core` (`writers_`, `mutex_`, `push`, `deliver`).
- Rule or table: ARCH3-R086, R139, `thread_safety` event_channel<E> write, try_write, read.

## Capacity is enforced per writer at write and again at the merge

- Decision: a write is refused (dropped and counted; try_write returns event_overflow) when the events already
  delivered this frame plus that writer's pending events reach 65536. The boundary merge then keeps only the first
  65536 events of the frame in delivery order and counts every later one as dropped. With one writer every drop
  happens at write; with several, a try_write that returned ok can still be dropped at the merge.
- Why: "drop the newest" must not depend on which worker wrote first. Any event beyond a writer's own first N
  cannot be among the frame's first N in delivery order, so the per-writer check is deterministic and bounds memory,
  and the merge truncation makes the kept set exactly the first 65536 in delivery order (RT-INV-EVT-05).
- Where: engine/runtime/src/event_channel.cpp `event_stream::refuse`, `count_drop`; events.hpp
  `detail::channel_core::push`, `append`.
- Rule or table: ARCH3-R141, ARCH3-R174 (`limits` event_capacity_default, no other value), RFP7.

## dropped() counts every refused event

- Decision: `dropped()` is the total since the channel was made of events refused at write, refused by try_write
  (event_overflow) and cut at the merge. A Debug payload refusal (event_payload_invalid) is not a drop.
- Why: the brief says write drops and counts; a try_write refusal drops the event too, and one counter keeps the
  "counts exactly" invariant simple.
- Where: engine/runtime/src/event_channel.cpp `event_stream::refuse`, `count_drop`.
- Rule or table: ARCH3-R141.

## The overflow warning is logged at end_frame

- Decision: one `sl::log` warning per frame with drops, system runtime.events, message "event overflow", fields
  type (event name), frame and dropped (that frame's count), logged by end_frame; a frame without drops logs nothing.
- Why: ARCH3-R166 allows log events only at boundaries, so the write path only counts.
- Where: engine/runtime/src/event_channel.cpp `event_stream::close_frame`.
- Rule or table: ARCH3-R141, ARCH3-R166.

## RFP7 is visited on every write and try_write

- Decision: inside `#if SL_RUNTIME_FAULTS`, every write and try_write visits RFP7; when it fires the write is
  refused exactly as at capacity (dropped and counted; try_write returns event_overflow).
- Why: the `failpoints` site is event_channel<E>::write and the outcome is "behaves as full".
- Where: engine/runtime/src/event_channel.cpp `event_stream::refuse`.
- Rule or table: `failpoints` RFP7, ARCH3-R020.

## Boundary steps: deliver, end_frame and attach

- Decision: `event_stream::deliver(frame)` merges the writer buffers into frame `frame`'s list and
  `event_stream::end_frame()` logs the frame's drops, drops the older list and starts the next. `attach(stream,
  scheduler)` registers deliver as a phase end hook (with `scheduler.current().frame_index`) and end_frame in the
  arena_flip boundary slot. Both are public so a runtime or a test can drive them without a scheduler.
- Why: the brief says "at each phase end hook" but names no slot for dropping the older list; arena_flip is the slot
  where frame-scoped storage turns over, after snapshot (the contributor sees both lists) and after
  observation_flush (where export runs).
- Where: engine/runtime/src/event_channel.cpp `attach`, `deliver_hook`, `flip_hook`; events.hpp
  `detail::channel_core::deliver`, `end_frame`.
- Rule or table: ARCH3-R095, R096, R139, `boundary_slots`; open for WO-096: R028 says a faulted frame must not flip
  its events, but attach flips unconditionally because fault handling is not built yet.

## event_ref comes from read_refs

- Decision: `read_refs(fn)` calls fn(const event_ref &, const event_envelope &, const E &), the ref being {frame of
  the event's list, type, seq}; `read(fn)` is as the brief. Readable order is the previous frame's list, then the
  current one.
- Why: the envelope carries no frame index, so a reader could not otherwise name an event as a cause.
- Where: events.hpp `event_channel::read_refs`, `detail::channel_core::read_refs`.
- Rule or table: ARCH3-R138.

## Channel shape and world helpers

- Decision: `event_channel<E>::make(const event_registry &frozen)` (invalid_argument unless frozen,
  event_type_unknown for an unregistered E) builds a move-only channel whose state is a `detail::channel_core<E>`
  behind a unique_ptr, reachable type-erased as `event_stream` (type, name, payload_type, dropped, deliver,
  end_frame, collect, capture, stage, commit_staged, discard_staged, hash). `add_event_channel<E>(world, registry)`
  adds it as a world resource; `find_event_channel<E>(world, registry)` finds it (event_type_unknown for an
  unregistered E, the world's not_found when no channel was added). A moved-from channel must not be used; the
  registry must outlive its channels.
- Why: world resources must be nothrow movable, while the frame hooks and the contributor need a stable address;
  the contributor and the exporter handle channels of different E.
- Where: events.hpp `event_channel`, `event_stream`, `detail::channel_core`, `add_event_channel`,
  `find_event_channel`.
- Rule or table: ARCH3-R137, `error_codes` event_type_unknown.

## channel_key is static and uses a reserved key range

- Decision: `event_registry::channel_key(id)` is a static constexpr function returning `{0x45560000 + id}`
  (`event_channel_key_base`); it does not check the id.
- Why: the brief writes a const member, but it reads no registry state (clang-tidy
  readability-convert-member-functions-to-static), and a fixed range keeps event channels clear of other resources.
- Where: events.hpp `event_registry::channel_key`, `event_channel_key_base`.
- Rule or table: not covered.

## Registry rules

- Decision: ids are 1.. in registration order (0 is none). add<E>(name, info) returns, in order, wrong_thread,
  type_registry_frozen, invalid_argument for an empty name or a byte outside 0x21..0x7E or an info whose size or
  alignment is not E's, already_exists for a repeated event name or a repeated E, then whatever
  `type_registry::add` returns (the info is copied into the registry's own type_registry, so its reflected name must
  be unique too). E must be trivially copyable, standard-layout and nothrow default constructible (static_assert).
  Added: `id_of<E>`, `find_key`, `name`, `payload_type`, `frozen`, `size`.
- Why: the brief names only type_registry_frozen and already_exists; the event name becomes the fabric type string
  "runtime.event.<name>", which must be printable ASCII; restore value-initialises payloads.
- Where: engine/runtime/src/event_registry.cpp `event_registry::add_raw`; events.hpp `event_registry`.
- Rule or table: ARCH3-R137, `error_codes`, `thread_safety` event_registry add, freeze.

## Debug validation

- Decision: `event_validation` is true when NDEBUG is not defined. Then write and try_write return
  event_payload_invalid, writing and counting nothing, when any f32 or f64 field is NaN or infinite, whatever its
  flags. Release writes without checking.
- Why: the brief fixes the rule to non-finite floats; ARCH3-R140 says "against reflected field flags", but a
  transient float that is NaN would still reach readers, so every float field is checked.
- Where: engine/runtime/src/event_channel.cpp `detail::payload_valid`; events.hpp `event_validation`,
  `event_channel::put`.
- Rule or table: ARCH3-R140.

## Contributor bytes, hash and restore

- Decision: runtime.events version 1 writes a u32le channel count, then per channel (ascending type id) its type id
  and both lists (previous, current), each a u64le frame index, a u32le count and per event the envelope (type u32,
  seq u32, system_index u16, tick u64, a cause flag u8 and the cause frame u64, type u32, seq u32) and a u32le-length
  payload of the fields flagged snapshot or hashed. The hash covers the same envelope fields and the payload fields
  flagged hashed, not the frame indexes. Restore requires the same channels and seq 1..n per list, stages every
  channel and commits only when all parse (snapshot_corrupt otherwise), clears the writer buffers and leaves
  correlations at their default {0, "process", 0}.
- Why: the brief fixes the name, version and "without correlation" only. A field flagged only hashed must be
  captured, or the hash would change across a round trip; frame indexes are snapshotted but not hashed, as for the
  clock contributor.
- Where: engine/runtime/src/event_contributor.cpp `events_contributor`, `detail::put_envelope`, `get_envelope`,
  `hash_envelope`; events.hpp `detail::channel_core::capture`, `stage`, `hash`, `detail::capture_fields`.
- Rule or table: ARCH3-R091, `determinism` pending events and correlation ids.

## Exporter shape

- Decision: `export_frame(std::uint64_t frame, std::span<const event_stream *const> channels)` publishes the events
  delivered in frame `frame` (either list), channels by ascending type id, as one `publish_batch`. Per envelope:
  type "runtime.event.<name>", schema ref `derive(type, source id, type string)` at 1.0, actor `derive(actor, source
  id, "runtime.events")`, scope tag "runtime", the event's correlation (scope "runtime" when empty), no causality,
  and the payload as one SLB/1 bytes value of every flagged field (transient included). A refusal by the source or
  the bus is errc::internal and publishes nothing (seqs the source already stamped stay spent); off the owner thread
  is wrong_thread.
- Why: the brief leaves the arguments open; fabric.event needs a type-class schema id, an actor-class actor and a
  subject or scope; an event_ref cause has no fabric event id to point to; ARCH3-R018 does not let the runtime return
  the fabric code event_invalid.
- Where: engine/runtime/src/event_export.cpp `event_exporter::export_frame`.
- Rule or table: ARCH3-R142, ARCH3-R018, ARCH1-R46.

## The correlation scope is a view

- Decision: `event_envelope::correlation` is the writer's `sl::log::current_correlation()`, scope included as a
  string_view; its storage must outlive the frame after the write (the scheduler's runtime/<instance> string and
  literals do).
- Why: the brief types the field as sl::log::correlation; copying the scope string on every write would allocate.
- Where: events.hpp `event_envelope`, `detail::channel_core::push`.
- Rule or table: ARCH3-R138, ARCH1-R48.

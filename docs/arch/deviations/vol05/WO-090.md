# WO-090 deviations: ECS queries (episode 093)

## Terms: which pass an argument, and optional<const T>

- Decision: read<T>, write<T> and optional<T> pass an argument to the body (const T&, T&, T*); optional<const T>
  passes const T*. with<T>, without<T>, changed<T> and added<T> are filters and pass nothing. Every tag names a
  plain component type (static_assert); `term_kind` is a public enum with `optional_read` and `optional_write`.
- Why: the brief lists "T* / const T* for optional" without saying how a query picks one; the const qualifier on
  the tag picks it and decides whether the term is a read or a write.
- Where: engine/runtime/include/sl/runtime/ecs/query.hpp `read`, `write`, `with`, `without`, `optional`, `changed`,
  `added`, `term_kind`.
- Rule or table: ARCH3-R114.

## The access set

- Decision: reads are read, optional<const T>, changed and added (a filter reads the tick column of T); writes are
  write and optional<T>; with and without are in neither (they test archetype membership, which only changes at
  boundaries). Both lists are ascending and unique, and a component in writes is not repeated in reads (write<T>
  with changed<T> gives writes {T}, reads {}).
- Why: the brief says the set is derived from the terms but not how filters count; a scheduler (WO-093, WO-094)
  needs disjoint lists in which a write implies the read.
- Where: engine/runtime/src/ecs_query.cpp `query_core::init`.
- Rule or table: ARCH3-R114, RT-INV-QUERY-04.

## Contradictory terms beyond the brief, and unregistered types

- Decision: besides with+without, read+write, a duplicate term and more than 32 terms, make() returns
  query_invalid for without<T> with any other term of T, and for two argument terms of one T (read, write,
  optional, either constness). An unregistered type returns component_unknown (the registry's code), checked after
  the 32-term limit and before the pairwise checks. Terms are checked on resolved ids, at run time.
- Why: a query that requires and excludes T, or binds T twice, can never be what the author meant; the brief's
  list is the minimum. component_unknown is the runtime code the world already returns for the same mistake.
- Where: engine/runtime/src/ecs_query.cpp `conflict`, `query_core::init`; query.hpp `query::make`.
- Rule or table: ARCH3-R114, `error_codes` query_invalid, component_unknown.

## Change filters combine with AND; stamps follow the filter

- Decision: every changed<T> and added<T> filter of a query must keep a row (AND). Within a row the filters read
  the ticks before the write terms stamp, so write<T> with changed<T> selects on the old tick. Only rows the filters
  keep are visited and stamped. optional<T> stamps where T is present; read and optional<const T> never stamp; no
  query writes an added tick. The wrap rule is `ecs::tick_later(tick, since)`, a public constexpr function.
- Why: ARCH3-R117 defines one filter; several filters and their order against the stamp are left open.
- Where: query.hpp `query::selected`, `query::stamp`, `tick_later`.
- Rule or table: ARCH3-R117, RT-INV-QUERY-05.

## for_each_chunk passes runs of selected rows

- Decision: for_each_chunk calls fn(std::span<const entity>, spans...) once per maximal run of consecutive selected
  rows of a chunk (once per chunk without change filters); the spans are std::span<const T> for read and
  optional<const T>, std::span<T> for write and optional<T>, empty for an absent optional component.
- Why: the brief names for_each_chunk but not its body signature; runs keep the body free of per-row filter tests
  and give exactly the rows for_each visits.
- Where: query.hpp `query::for_each_chunk`, `query::call_run`, `detail::term_span`.
- Rule or table: ARCH3-R114, ARCH3-R117.

## The match cache: creation indices, room reserved at make, full rescan on restore

- Decision: the cache holds the creation indices of the matched archetypes in a std::vector reserved for
  max_archetypes (4096) entries by make(), so iteration never allocates. It also keeps the world's address (compared,
  never dereferenced), the archetype count scanned and the generation seen. A refresh scans only
  archetypes()[scanned..] when the world is the same and the generation moved by exactly the number of new
  archetypes; otherwise (another world, restore_from, which adds staged + 1 to the generation) it clears the cache and
  scans every archetype. A world destroyed and replaced at the same address whose generation history happens to
  match is not detected.
- Why: ARCH3-R115 asks for incremental matching from the generation; restore_from replaces every archetype, which
  the generation alone does not say. Indices instead of pointers keep no pointer into the growing archetype list.
- Where: engine/runtime/src/ecs_query_match.cpp `query_core::refresh`; ecs_query.cpp `query_core::init`.
- Rule or table: ARCH3-R115, RT-INV-QUERY-02.

## What the counters count

- Decision: archetypes_visited() counts the archetypes the match cache examined since make (0 for a refresh with no
  new archetype); chunks_visited() counts the non-empty chunks iterated, including chunks whose rows the change
  filters all skip, and par_for_each counts every chunk of its batches on the calling thread. Empty chunks are not
  visited: rows are dense, so iteration of an archetype stops at its first empty chunk.
- Why: the brief names both counters without defining them; RT-INV-QUERY-02 needs the archetype count.
- Where: query.hpp `query::archetypes_visited`, `query::chunks_visited`; ecs_query_match.cpp.
- Rule or table: ARCH3-R115.

## A world of another registry

- Decision: for_each and for_each_chunk on a world whose registry is not the query's visit nothing; par_for_each
  returns invalid_argument.
- Why: component ids are only meaningful in their registry; the void signatures of the brief leave no error
  channel, and SL_ASSERT is reserved for the `assertions` list.
- Where: query.hpp `query::for_each`, `query::for_each_chunk`, `query::par_for_each`; `query_core::same_registry`.
- Rule or table: ARCH3-R018, ARCH3-R019.

## par_for_each: batching, submission and failures

- Decision: a batch is a run of whole non-empty chunks of the matched archetypes in creation order that closes once
  its chunks hold at least par_batch_min_rows (4096) rows, counting every row of a chunk whatever the change
  filters select, so the partition depends only on the row counts. Batches are numbered from 0 (the ordered_key
  chunk_index) and passed to the body. Each is one frame-priority, any-affinity job named "ecs.par_for_each"
  submitted with try_submit and a job_counter; a job_capacity refusal runs that batch on the calling thread; any
  other refusal stops submitting, waits for the submitted batches and returns the error (rows of later batches are
  then not visited). After the helping wait, a batch that did not run (RFP2, cancellation) gives job_failed. The
  batch body is a named struct (`batch_job`, 32 bytes) whose context lives on the caller's stack.
- Why: the brief fixes the partition but not the submit path; running a batch inline at capacity keeps the
  partition and the visit-once property, and counting completed batches is the only way to see a skipped body
  through a counter wait.
- Where: query.hpp `query::par_for_each`, `query::launch`, `query::run_batch`, `query::batch_job`.
- Rule or table: ARCH3-R116, `limits` par_batch_min_rows, `determinism` ordered_key, RT-INV-QUERY-03.

## Thread safety of a query object, and the background-job check

- Decision: a query object belongs to one system: its cache and counters change on every call, so it must not be
  iterated from two threads at once; par_for_each refreshes the cache and counts chunks on the calling thread, and
  its workers only read the cache. Query iteration does not run the world's background-job assertion
  (world::check_access is private) and checks no thread.
- Why: the `thread_safety` table makes queries worker-only without saying whether a query object is shared; the
  world exposes no public access check.
- Where: query.hpp header comment, `query::run_batch`.
- Rule or table: ARCH3-R175, `thread_safety` ecs::query.

## Bodies must be noexcept

- Decision: for_each, for_each_chunk and par_for_each static_assert that the body is nothrow invocable with the
  argument types of the terms.
- Why: the runtime is noexcept throughout (R-RT-THROW, R-RT-NOEXCEPT); a throwing body inside a job would
  terminate.
- Where: query.hpp `query::row_body`, `query::chunk_body`, `query::par_body`.
- Rule or table: ARCH3-R017, runtime-lint R-RT-NOEXCEPT.

## Names beyond the brief and no failpoints

- Decision: query.hpp adds `max_query_terms` (= max_components_per_archetype, 32), `par_batch_min_rows`,
  `term_kind`, `tick_later` and the non-template `detail::query_core` (terms, access set, cache, counters) that the
  two sources implement. The query area visits no failpoint.
- Why: the brief puts most of the work in header templates; the non-template core keeps the checks and the cache in
  src/ecs_query.cpp and src/ecs_query_match.cpp as the brief names them. No `failpoints` row names a query site.
- Where: engine/runtime/include/sl/runtime/ecs/query.hpp `detail::query_core`.
- Rule or table: `limits`, `failpoints`.

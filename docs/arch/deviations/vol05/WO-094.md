# WO-094 deviations: system scheduling contracts (episode 094)

Builder record for ecs/system.hpp, src/ecs_system_scheduler.cpp, ecs_system_graph.cpp, ecs_system_batches.cpp,
ecs_system_export.cpp, ecs_access_guard.cpp, testing/sim_fixture.{hpp,cpp} and the seven sched_* test files.
SL-ARCH-003 was not edited.

## The scheduler is built on a job system

- Decision: `system_scheduler(jobs::job_system &)` takes the job system at construction; `build(frame_scheduler &,
  world &, command_queue &)` binds the rest. The owner thread is the constructing thread.
- Why: exclusive systems and serial chains submit jobs before any frame exists; the frame scheduler is only known
  at build.
- Where: system.hpp `system_scheduler`.
- Rule or table: ARCH3-R121, `thread_safety` system_scheduler.

## system_desc carries the queries it will run

- Decision: `system_desc::queries` lists the component_access of each query the body uses; add refuses
  (access_conflict) a query its access_set does not cover.
- Why: the Debug audit can then fail at add, before any frame, instead of only when the body runs.
- Where: system.hpp `system_desc`, ecs_system_scheduler.cpp `add`, ecs_access_guard.cpp `detail::covers`.
- Rule or table: ARCH3-R122, RT-INV-SCHED-03.

## access_set normalisation

- Decision: add sorts and deduplicates every list and drops a read that is also a write (component and resource).
- Why: conflict tests, the guard and the export then use binary search and print one canonical form.
- Where: ecs_system_scheduler.cpp `normalize`.
- Rule or table: ARCH3-R122, R126.

## Names are unique across phases

- Decision: a second system with a used name fails with already_exists in any phase; a before/after name that is
  unknown or names a system of another phase fails the build with system_unknown.
- Why: constraints only order within a phase; a cross-phase name is a spec error, not a no-op.
- Where: ecs_system_scheduler.cpp `add`, ecs_system_graph.cpp `order_phase`.
- Rule or table: ARCH3-R123.

## Kahn with a min-heap; the cycle names its members

- Decision: each phase is ordered by Kahn's algorithm whose ready set is a min-heap on registration index, so ties
  break by registration order; leftover nodes form schedule_cycle, whose message lists the phase and only the
  systems on a cycle (not those merely downstream of it). A failed build registers nothing with the frame scheduler.
- Where: ecs_system_graph.cpp `order_phase`, `cycle_members`.
- Rule or table: ARCH3-R123, R124, RT-INV-SCHED-02, -04.

## Edges only between conflicting systems

- Decision: a task depends on an earlier system of its phase only when the two conflict (write-read, write-write on
  a component or resource, or either exclusive), transitively reduced; a task with more than
  jobs::job_max_dependencies predecessors hands its earliest one p to its next one q (p < q), which keeps it after
  p, until every task fits the job limit.
- Where: ecs_system_graph.cpp `conflict`, `plan_edges`, `build`.
- Rule or table: ARCH3-R122, RT-INV-SCHED-01, -05.

## Exclusive systems run through an owner job

- Decision: an exclusive system is a task whose body submits a main-affinity `owner_job` and waits on it, so it
  runs on the owner thread with no other system of its phase in flight.
- Where: ecs_system_scheduler.cpp `run_on_owner`.
- Rule or table: ARCH3-R122.

## serial_canonical is one chain

- Decision: under serial_canonical every system of a phase runs inline on the owner thread in system_index order,
  and par_for_each batches run inline in ordered_key order; this is the oracle of RT-INV-SCHED-06.
- Where: ecs_system_scheduler.cpp `run_serial_phase`, ecs_system_batches.cpp `batch_cursor`.
- Rule or table: ARCH3-R090, R125.

## Inline batches by batch_cursor

- Decision: an inline (serial) par_for_each numbers batches exactly as the parallel split (close at
  par_batch_min_rows rows) by walking archetypes and chunks to the entity column holding the first row.
- Where: ecs_system_batches.cpp `batch_cursor::locate`.
- Rule or table: ARCH3-R125.

## Change ticks per system

- Decision: each system_record keeps its own last_run; a system writes at `change_tick + 1 + system_index`, and
  the world tick advances by n+1 per tick for n systems, so changed() filters see every write of the previous run
  and none of their own. WO-093's `last_run_ticks` is not used.
- Where: ecs_system_scheduler.cpp `begin_phase`, `end_phase`.
- Rule or table: ARCH3-R092 change stamps.

## phase_active

- Decision: the scheduler marks the world phase-active from begin_frame through post_tick and inactive from
  observe on (world::set_phase_active), so the world knows when systems may be running; a phase without systems
  registers no task.
- Where: ecs_system_scheduler.cpp `begin_phase`.
- Rule or table: ARCH3-R092 structural changes at the boundary.

## The Debug access guard

- Decision: with access_guard_enabled, a non-exclusive system whose query, resource access or command use is not
  declared fails once with undeclared_access (job failed, last_error set, further access refused for that run);
  exclusive systems are never audited; commands need structural or exclusive.
- Where: ecs_access_guard.cpp `allow_query`, `allow_resource`, `check_commands`, `violation`.
- Rule or table: ARCH3-R122, RT-INV-SCHED-03.

## RFP5

- Decision: the rfp5 failpoint (SL_RUNTIME_FAULTS) fails a system job with job_failed after its body; the frame
  continues and failures() counts it.
- Where: ecs_system_scheduler.cpp; test sched_access_guard_test.cpp.
- Rule or table: SL-ARCH-003 failpoint table.

## No per-batch command buffers

- Decision: a structural system records commands on its worker's buffer from command_queue; par_for_each batches
  get no command buffer of their own. pending_entity.buffer is the recording worker and is not deterministic; only
  the playback order (ordered_key) is.
- Where: system.hpp `system_context::commands`.
- Rule or table: ARCH3-R127.

## Extra accessors

- Decision: `order(phase)`, `system_index(id)`, `failures()`, `last_error(id)`, `last_flush()`, `built()` and
  `policy()` are public for the tests and tools.
- Where: system.hpp `system_scheduler`.

## sched_rig and sim_fixture

- Decision: testing::sched_rig is the bare stack (jobs, frame scheduler at 50 Hz, the eight world_gen components,
  world, queue, scheduler); `make_on` shares a job system across many short schedules. sim_fixture::make runs one
  priming frame (the first clock sample runs no tick), so each run frame is exactly one tick. The fixture uses 4400
  entities (two batches) and RT-INV-SCHED-06 runs 16 ticks per run to stay inside the 60 s entry limit under TSan.
- Where: engine/runtime/testing/sim_fixture.{hpp,cpp}.
- Rule or table: ARCH3-R090, RT-INV-SCHED-06.

# WO-087 deviations: runtime reflection (episode 096)

Builder record for reflect.hpp, src/reflect_registry.cpp, reflect_codec.cpp, reflect_binding.cpp, reflect_invoke.cpp
and the six refl_* test files. SL-ARCH-003 was not edited.

## What a transient type is

- Decision: a type is transient when it binds no field (no field has a Fabric number); a document-bound type has a
  schema type and at least one bound field. `type_registry::add` returns invalid_argument for a type with a schema
  type and no bound field, a type without a schema type that has bound fields, an empty schema type, and a field
  flagged transient that has a Fabric number. `fabric_binding::bind` of a type without a schema type is
  invalid_argument (the brief).
- Why: ARCH3-R135 says "a transient type MUST carry no schema type" and ADR-0027 splits component types into
  document-bound (one binding) and transient, but neither defines transient for a type_info, which has no type flag.
- Where: engine/runtime/src/reflect_registry.cpp `check_fields`; engine/runtime/src/reflect_binding.cpp
  `fabric_binding::bind`.
- Rule or table: ARCH3-R135, ADR-0027, RT-INV-REFL-05.

## add() checks the layout and copies every string

- Decision: add() takes `const type_info &` and stores an owned copy: the type name is the map key and field names,
  method names and parameter lists are copied into the entry, so the views of the returned type_info point into the
  registry. add() sets `type_key = type_key_of(name)` whatever the caller passed. It refuses with invalid_argument an
  empty name, size 0, an alignment that is not a power of two or does not divide the size, more than 64 fields, a
  field with an empty or repeated name, an unknown kind, a size that is not the kind's (or 0 for bytes_fixed), offsets
  that overlap or are not strictly ascending (declaration order), a field past the end, an unknown flag bit,
  transient together with snapshot or hashed, a repeated Fabric number, and for methods an empty or repeated name, a
  null invoker, more than 4 parameters or a record_id or bytes_fixed parameter. A repeated name, or an FNV-1a-64 key
  equal to another type's, is already_exists. Checks run in that order after wrong_thread and type_registry_frozen.
- Why: the brief names type_registry_frozen, already_exists and invalid_argument beyond 64 fields; the walk is only
  safe (never reading padding or past the object) on a checked layout, and a registered type must not depend on the
  caller's string storage. Ascending offsets are what declaration order means for a standard-layout type.
- Where: engine/runtime/src/reflect_registry.cpp `type_registry::add`, `check_type`, `check_fields`, `check_methods`.
- Rule or table: ARCH3-R133, ARCH3-R134, `limits` max_fields_per_type, max_method_arity, `error_codes`.

## Owner thread and freeze

- Decision: the owner thread is the thread that constructed the registry; add and freeze from another thread return
  wrong_thread. freeze() on a frozen registry succeeds. Reads (find, field, method, dump) have no thread check and
  are safe from any thread once frozen.
- Why: the `thread_safety` row makes add and freeze owner-thread and allows "wrong_thread or a Debug assertion"; the
  error keeps Release safe, as WO-088 does for the world.
- Where: engine/runtime/src/reflect_registry.cpp `type_registry::type_registry`, `add`, `freeze`.
- Rule or table: ARCH3-R175, `thread_safety` reflect type_registry add, freeze, `immutability` type registry.

## Method lookup, the method_invoker alias and argument checks

- Decision: `type_registry::method(type, name)` finds a method and returns type_unknown when it is absent (the
  `error_codes` row type_unknown covers "method lookup"); field lookup is `type_registry::field` (field_unknown).
  Both are static members: they read only the type_info they are given (clang-tidy
  readability-convert-member-functions-to-static and cppcheck functionStatic reject a const member that ignores the
  registry), so `reg.field(t, name)` in the brief is spelled `type_registry::field(t, name)`.
  The invoker type is named `method_invoker`. invoke() returns reflect_mismatch for a wrong count, an argument whose
  variant alternative is not the parameter's (bool, int64 for i8..i64, uint64 for u8..u64, double for f32 and f64,
  entity_bits) or that does not fit the width (integers by range, f32 by magnitude, NaN and infinities pass), and
  invalid_argument for a null object or invoker.
- Why: the brief lists method lookup errors only through `error_codes`; a value the invoker would have to narrow out
  of range is a wrong argument, and a double above FLT_MAX converted to float is undefined behaviour.
- Where: engine/runtime/include/sl/runtime/reflect.hpp `method_invoker`, `type_registry::method`;
  engine/runtime/src/reflect_invoke.cpp `invoke`, `accepts`.
- Rule or table: ARCH3-R133, `error_codes` type_unknown, reflect_mismatch.

## Builder surface beyond the brief

- Decision: type_builder has `field(name, offset, kind, flags, fabric_field)` for scalar kinds (size from
  `kind_size`), `bytes(name, offset, size, flags, fabric_field)` for bytes_fixed, `field_of<M>` (used by the macros:
  kind and size from the member type; bool, the fixed-width integers, float, double, entity_bits,
  sl::fabric::record_id, std::array of std::byte or std::uint8_t), `method`, `schema`, `info()` and `build()`.
  `SL_RT_FIELD_BOUND(builder, T, member, flags, no)` is SL_RT_FIELD with a Fabric field number. Also added:
  `to_string(field_kind)`, `kind_size`, `any(field_flags)`, `|=`/`&=`, `type_key_of`, `encoded_size`,
  `type_registry::frozen()`/`size()`, and `fabric_binding::type()`, `fabric_type()`, `fields()` with
  `fabric_binding::bound_field`; the `limits` values are the constants `max_fields_per_type` (64) and
  `max_method_arity` (4). `build()` returns a copy (the builder stays usable) under an inline
  `cppcheck-suppress returnByReference`; `info()` is the by-reference view.
- Why: field(name, offset, kind, ...) cannot size a bytes_fixed field, and SL_RT_FIELD has no Fabric number argument;
  WO-088's layout digest needs the field walk's sizes.
- Where: engine/runtime/include/sl/runtime/reflect.hpp `type_builder`, `SL_RT_FIELD_BOUND`, `fabric_binding`.
- Rule or table: ARCH3-R133, ARCH3-R174.

## Field selection and the byte format

- Decision: a field is walked when its flags intersect `select`; a field with no flag is never encoded or hashed. The
  encoding has no header, tags or lengths: per field its little-endian bytes (bool one byte 0 or 1, read as a byte so a
  stored value other than 0 or 1 encodes as 1; entity index then generation; record_id and bytes_fixed raw). hash_into
  uses the state_hasher calls of each kind (boolean, iN, uN, f32, f64, two u32 for entity, one `bytes` value for
  record_id and bytes_fixed) and adds no type key. decode needs exactly `encoded_size` bytes and bool bytes 0 or 1
  (invalid_argument otherwise, checked before any write); it writes canonical floats. encode and hash_into
  SL_ASSERT a non-null object.
- Why: the brief fixes order, endianness and canonical floats but not the selection rule, the bool byte or the decode
  errors; invalid_argument is the core code for malformed input (ARCH3-R018 allows no other here).
- Where: engine/runtime/src/reflect_codec.cpp `encode`, `decode`, `hash_into`, `selected`.
- Rule or table: ARCH3-R134, `determinism` components flagged hashed / snapshot, `limits` canonical_nan_f32/f64.

## Binding kinds, defaults and conversion errors

- Decision: bind requires a frozen registry (invalid_argument otherwise) and `fabric_type` equal to the schema type,
  naming a struct record type (component_schema_mismatch otherwise). A field binds when the Fabric field's type,
  resolved through tagged bases (at most 64 steps), has the same kind and width: bool, iN to iN, uN to uN, f32, f64;
  record_id binds to id or ref; entity and bytes_fixed never bind. Unbound Fabric fields are ignored both ways.
  to_value writes every bound field (integers as uint or nint, ids as id values) and returns invalid_argument for a
  NaN or infinite float, which Fabric cannot hold. from_value stages every field first and writes only when all fit:
  an absent field takes the Fabric default, an absent optional field without one is written as zero, and an absent
  required field, a wrong value kind or an out-of-range integer is invalid_argument. path_of returns {field(no)} for
  a bound number and the empty path otherwise.
- Why: the brief lists the compatible kinds but not tagged types, defaults, a value that does not conform or how
  Fabric's encode_invalid surfaces; runtime APIs return runtime or allowed core codes only (ARCH3-R018).
- Where: engine/runtime/src/reflect_binding.cpp `resolved_kind`, `compatible`, `fabric_binding::bind`, `to_value`,
  `from_value`, `path_of`.
- Rule or table: ARCH3-R135, ARCH3-R018, ADR-0027.

## Everything is noexcept

- Decision: every function of reflect.hpp is noexcept, including those that allocate (add, dump, encode, the builder,
  bind, to_value, from_value); an allocation failure terminates.
- Why: the runtime convention (WO-088's component_registry::add is noexcept) and RT-INV-REFL-04 "nothing throws".
- Where: engine/runtime/include/sl/runtime/reflect.hpp.
- Rule or table: ARCH3-R010, ADR-0009.

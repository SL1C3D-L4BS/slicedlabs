# WO-083 deviations: ECS entity lifecycle (episode 091)

Builder record for ecs/entity.hpp, src/ecs_entity.cpp, src/ecs_entity_map.cpp and the six ent_*_test.cpp files.
SL-ARCH-003 was not edited.

## The 64-bit form of a handle puts the index in the high word

- Decision: `entity::bits()` is `(index << 32) | generation`; added `entity::from_bits(u64)` as its inverse.
  `null_entity.bits()` is 0.
- Why: ARCH3-R101 fixes the two fields but not their order inside 64 bits. Index-high makes the order of bits() equal
  the defaulted `operator<=>` (index, then generation), so a list sorted by either is sorted by both. The handle layout
  is runtime ABI (ARCH3-R032); WO-095 snapshots and WO-097 records can store bits() and read it back.
- Where: engine/runtime/include/sl/runtime/ecs/entity.hpp `entity::bits`, `entity::from_bits`.
- Rule or table: ARCH3-R101, ARCH3-R032, `limits` entity_index_bits, entity_generation_bits.

## Members beyond the brief

- Decision: entity_allocator also has `retired_count()`, `next_index()`, `max_entities()`, `page_count()` and
  `page_address(page)` (the generation array of an allocated page, nullptr otherwise); `state` has a defaulted
  `operator==`; entity.hpp names the `limits` values as constants (entity_generation_first, entity_generation_retire,
  entity_reuse_fifo_threshold, entity_page_records, max_entities_default, the two bit widths). alive() and
  free_count() are noexcept. Both classes are neither copyable nor movable.
- Why: RT-INV-ENT-04 must observe that pages never move and RT-INV-ENT-02 that a slot is retired; "changes nothing"
  is checked by comparing captures. Readers may hold page addresses, so the allocator cannot move.
- Where: entity.hpp `entity_allocator`, `entity_allocator::state`.
- Rule or table: ARCH3-R104, ARCH3-R174, `limits`.

## A page holds generations, free-FIFO links and alive bits

- Decision: a page is one 64-byte-aligned block of 33,280 bytes from the allocator's resource: 4096 u32 generations,
  4096 u32 links of the free FIFO and a 4096-bit alive map. The free FIFO is intrusive (head, tail and count in the
  allocator, links in the pages), so destroy never allocates. A fresh page has every generation 1, no link and nothing
  alive. Pages are allocated in ascending order by create (and restore), so the allocated pages are always pages
  0..page_count()-1, and they are released only by the destructor.
- Why: the brief says "pages of 4096 u32"; the alive bit tells a live slot from a free slot of the same generation
  (destroy bumps the generation, but the next create of a fresh or reused slot must not make an old handle alive), and
  an external FIFO container would make destroy allocate (and fail) under ADR-0023.
- Where: src/ecs_entity.cpp `entity_allocator::page`, `push_free`, `pop_free`, `allocate_page`.
- Rule or table: ARCH3-R102, ARCH3-R104, `limits` entity_page_records.

## The page table is sized once in the constructor

- Decision: the constructor allocates a `std::pmr::vector<page *>` of ceil(max_entities / 4096) entries from the given
  resource (the pmr path, which SL_ASSERT-aborts on exhaustion without an upstream; 8 MiB at max_entities 2^32 - 1,
  8 KiB at max_entities_default). It never grows, so a reader during a phase never sees it move.
- Why: a constructor cannot return sl::result and the brief gives the constructor no error path; growing the table in
  create would move it under concurrent readers.
- Where: src/ecs_entity.cpp `entity_allocator::entity_allocator`; entity.hpp `entity_allocator::pages_`.
- Rule or table: ARCH3-R104, ARCH3-R042, ADR-0023.

## Pages carry the resource's default tag

- Decision: pages are allocated with `memory.default_tag()`; the allocator names no tag of its own.
- Why: `ecs.entities` is registered by WO-096 at runtime start (runtime_tag_names), and a tracking_resource with a
  registry refuses an unregistered tag. The world (WO-088) passes a resource whose default tag is ecs.entities.
- Where: src/ecs_entity.cpp `entity_allocator::allocate_page`.
- Rule or table: ARCH3-R045.

## create: failure modes and RFP10 parameters

- Decision: create visits RFP10 once at its top, before choosing an index. param 1 fast-forwards the chosen slot (fresh
  or reused) to generation 0xFFFFFFFE; every other param (0 included, the default of arm) forces entity_capacity. A
  new page that cannot be allocated is out_of_memory. Every error leaves the allocator unchanged (a forced capacity
  allocates nothing, a failed page leaves next_index as it was); a fast-forward whose create fails anyway is lost.
- Why: the brief names params 0 and 1 only; treating unknown params as capacity keeps an armed visit from being a
  silent no-op. out_of_memory is the only other way create can fail (ARCH3-R018 lists it as a runtime code).
- Where: src/ecs_entity.cpp `entity_allocator::create`.
- Rule or table: `failpoints` RFP10, ARCH3-R020, ARCH3-R104.

## No owner-thread check

- Decision: create, destroy and restore do not check the calling thread; nothing in the allocator is atomic. Readers
  (is_alive, check, assume_alive, entity_map lookups) are safe from any thread only while no mutation runs, which the
  phase structure guarantees (a TSan-run case reads from four threads during a read-only phase).
- Why: ARCH3-R175 allows wrong_thread or a Debug assertion, but the allocator does not know the runtime's owner thread
  in Volume 05 wave 3; the world (WO-088), which owns it, holds that check for every structural call. "Grow only at
  sync boundaries" (ARCH3-R104) follows from the same rule.
- Where: entity.hpp `entity_allocator`; tests/unit/runtime/ent_stale_test.cpp (readers case).
- Rule or table: ARCH3-R104, ARCH3-R175, `thread_safety` ecs::entity_allocator.

## capture and restore

- Decision: capture lists the generation of every index below next_index, the free FIFO oldest first and the retired
  indices ascending (the indices whose generation is 0xFFFFFFFF). restore validates before it changes anything:
  invalid_argument when next_index is above max_entities, generations has another size than next_index, a free or
  retired index is out of range or listed twice (or in both lists), a free slot has generation 0xFFFFFFFF, a retired
  slot has another generation, a slot has generation 0, or a 0xFFFFFFFF slot is not listed as retired. Every unlisted
  index below next_index is alive. Missing pages are allocated first (out_of_memory releases the ones allocated by the
  call and changes nothing); then every allocated page is reset in place and the state written, so pages never move
  and slots above next_index are fresh again.
- Why: the brief gives the signatures only; WO-095 restores snapshots through it and ARCH3-R145 requires the
  continuation to equal the original (RT-INV-ENT-03 checks this).
- Where: src/ecs_entity.cpp `entity_allocator::capture`, `entity_allocator::restore`.
- Rule or table: ARCH3-R143, ARCH3-R145, `determinism` entity allocator.

## Error messages and noexcept

- Decision: destroy and check put the handle into the stale_entity message ("stale entity handle {i, g}"), create puts
  max_entities into the entity_capacity message. Building the message allocates inside a noexcept body; heap
  exhaustion there terminates, as in WO-079.
- Why: diagnostics; ADR-0023 makes OOM an abort.
- Where: src/ecs_entity.cpp `describe`, `create`, `destroy`, `check`.
- Rule or table: ARCH3-R010, ADR-0023.

## The unchecked accessor is NDEBUG-gated

- Decision: `assume_alive` is `SL_DEBUG_ASSERT(is_alive(e), "unchecked access through a stale entity handle")`, which
  sl/core/assert.hpp compiles out when NDEBUG is defined (Release); Debug, gcc-debug and every sanitizer preset keep it.
  The RT-INV-ENT-06 assertion case skips its assertion checks with a message under NDEBUG.
- Why: the brief names SL_DEBUG_ASSERT; the `assertions` table lists the stale-handle assertion.
- Where: src/ecs_entity.cpp `entity_allocator::assume_alive`; tests/unit/runtime/ent_access_test.cpp.
- Rule or table: ARCH3-R103, `assertions`.

## entity_map does not return stale_entity

- Decision: entity_map has no allocator, so key_of and find never answer stale_entity: key_of(e) is the key while e is
  mapped (dead or alive) and not_found otherwise. A caller that needs the liveness answer calls
  entity_allocator::check (the link, WO-097, does both).
- Why: the brief fixes not_found for key_of; the `error_codes` row of stale_entity also names "ecs::entity_map lookups
  of a dead entity", which needs an allocator the brief does not give the map. WO-100 should reconcile the row.
- Where: entity.hpp `entity_map::key_of`, `entity_map::find`.
- Rule or table: `error_codes` stale_entity, ARCH3-R105.

## entity_map details

- Decision: insert of the null entity is invalid_argument; checks run in the order null, key, entity, and a refused
  insert changes nothing. Nodes of both std::pmr::map come through the pmr path of the given mem::resource (exhaustion
  SL_ASSERT-aborts; there is no out_of_memory result). insert, find, key_of and erase are not noexcept (they copy Key);
  for_each takes the callable by value and calls fn(const Key &, entity) in ascending key order. Key must be ordered by
  operator< (fabric::record_id is). The error results are built by five non-template functions in
  src/ecs_entity_map.cpp.
- Why: the brief does not cover the null entity, allocation failure or exception specifications; a map that throws
  bad_alloc is impossible with a mem::resource, whose do_allocate never throws.
- Where: entity.hpp `entity_map`; src/ecs_entity_map.cpp `detail::entity_map_*`.
- Rule or table: ARCH3-R105, ARCH3-R042, ARCH3-R087 (no unordered container).

## Test shapes

- Decision: RT-INV-ENT-01 runs 1e6 x SL_RUNTIME_STRESS_SCALE creates and as many destroys (a cycle is one create and
  one destroy) on max_entities 8192, the live population following a seeded target redrawn every 8192 steps
  (splitmix64, seed 0x5EED0910001), so the fresh, FIFO and exhausted paths all run; it checks every created generation
  against the last destroyed one of its index, probes recently destroyed handles every step and all last destroyed
  handles at the end. RT-INV-ENT-03 compares every create of a 4e5 x scale seeded history with an independent
  reference model of the reuse rule. The RFP10 cases of RT-INV-ENT-02 and RT-INV-ENT-04 skip when the failpoints are
  compiled out; RT-INV-ENT-02 also reaches saturation through restore, which runs in every build. RT-INV-ENT-04 injects
  page allocation failures with testing::failing_resource (call 1 is the page table).
- Why: the invariant texts fix the totals and the outcomes but not the workload; each file runs under 1 s in Debug.
- Where: tests/unit/runtime/ent_*_test.cpp.
- Rule or table: RT-INV-ENT-01 to RT-INV-ENT-06, `limits` SL_RUNTIME_STRESS_SCALE_default.

# WO-096 deviations: runtime lifecycle and recovery (episode 081)

## work_stealing is the default queue

- Decision: `runtime_config::queue` defaults to `queue_kind::work_stealing` (the Chase-Lev deque from
  `make_ws_queue` with `make_steal_policy`). `queue_kind::locked` keeps the locked deque with the reference policy.
- Why: the brief makes the switch depend on TSan evidence. `just runtime-san tsan steal` passed on 2026-10-21 (exit 0,
  6 of 6 tests, about 7 s), and `just runtime-san tsan life` passes with the new default. life_background_test runs
  under both queue kinds.
- Where: engine/runtime/include/sl/runtime/runtime.hpp `runtime_config::queue`, engine/runtime/src/runtime_lifecycle.cpp
  `runtime::start_jobs`.
- Rule or table: ARCH3-R024; WO-086's open item.

## Systems and contributors are staged before start

- Decision: `add_system` and `add_contributor` are accepted only in Created, on the owner thread. Start then gives
  the staged systems to the system scheduler and builds it. `add_system` after start returns invalid_state;
  off the owner thread it returns wrong_thread.
- Why: the system scheduler is built inside start (step 6), so there is nothing to add to before then.
- Where: engine/runtime/src/runtime_core.cpp `runtime::add_system`, engine/runtime/src/runtime_lifecycle.cpp
  `runtime::start_frames`.
- Rule or table: ARCH3-R022, R023.

## Start order, and what an unwind leaves behind

- Decision: start runs these steps in order:
  1. the platform instance_id check (0 gives runtime_failure)
  2. the memory root: tags, three tracking resources (runtime.root, runtime.world, runtime.frame), diagnostics, and a
     root block that holds the fault-tick ring
  3. the tag freeze
  4. the component, type and event freezes
  5. the jobs
  6. the frames, world, command queue and system scheduler
  7. wire_hooks, then the frame build
  8. the tick-0 snapshot

  A failure tears down every part in reverse and moves Starting to Created. The registry freezes are idempotent and
  are not undone; a retry skips the tags that already exist.
- Why: the registries have no unfreeze, and a retry must still work (RT-INV-LIFE-02).
- Where: engine/runtime/src/runtime_lifecycle.cpp `runtime::start`, `start_steps`, `memory_root`, `teardown`.
- Rule or table: ARCH3-R022, R023.

## RFP0 is swept only over the memory root

- Decision: life_startup_unwind_test fires RFP0 at visit 1, both one-shot and sticky. It does not fire RFP0 beyond the
  memory root.
- Why: firing RFP0 inside `world::make` trips the debug assert in WO-088's std::pmr entity allocator. That is outside
  this work order's paths.
- Where: tests/unit/runtime/life_startup_unwind_test.cpp.
- Rule or table: ARCH3-R023; open issue for the ecs owner.

## The logical tick is not rewound on restore

- Decision: a restore puts back the world and the contributors, but the frame clock keeps its tick. Tests therefore
  compare state hashes by applied-tick count, using a map from tick to applied ticks, not by logical tick.
- Why: frame_scheduler has no tick rewind (WO-089's open item).
- Where: engine/runtime/src/runtime_recovery.cpp `runtime::restore_newest`; tests/integration/runtime/life_recovery_test.cpp.
- Rule or table: ARCH3-R029; open issue for WO-098.

## The background epoch is a discard at restore and shutdown

- Decision: every restore and every shutdown drains the undelivered background results and drops them.
  `discarded_results()` counts them. There is no epoch counter.
- Why: jobs quiesce before the end_frame slots, so no result from before the restore can arrive after the drain.
- Where: engine/runtime/src/runtime_recovery.cpp `runtime::discard_background`.
- Rule or table: ARCH3-R030.

## What a faulted frame plays back

- Decision:
  - The ecs scheduler flushes per phase, so phases that ran before the failing system have already been played back.
    Under restore_snapshot, the restore undoes them.
  - After a fatal job report, a phase-end hook registered ahead of the system scheduler's hook clears the command
    queue (`discard_after_fatal`), so later phases play nothing.
  - fault_check clears the queue again.
  - Event buffers of the faulted frame still flip (WO-092). A host that wants them restored adds an
    events_contributor.
- Why: the brief says the faulted frame's commands are never played back, but the per-phase flush comes from WO-088.
- Where: engine/runtime/src/runtime_fault.cpp `runtime::discard_after_fatal`, `runtime::on_fault_check`.
- Rule or table: ARCH3-R028.

## Fault naming, the recovery window and playback_oom

- Decision:
  - system_fail names the first system whose last_error changed since the last check (otherwise the first system with
    an error), as `<name>#<index>`, from the names the runtime recorded at start.
  - The window counts the faults with `tick - t <= recovery_window_ticks`. More than max_recoveries gives
    recovery_failed and Stopping.
  - playback_oom is detected from `last_flush` but has no test.
- Why: the system scheduler keeps no names, and the brief does not say whether the window bound is inclusive.
- Where: engine/runtime/src/runtime_fault.cpp `runtime::detect_fault`, engine/runtime/src/runtime_recovery.cpp
  `runtime::over_recovery_limit`.
- Rule or table: ARCH3-R028, R029.

## Swaps

- Decision: `request_swap` stays void. `swap_status()` and `swap_code()` report the outcome. data and
  gameplay_function swaps keep the pre-swap snapshot until the health window ends. A fault during the window rolls the
  swap back.
- Why: the brief's signature is void, so the outcome code needs its own read.
- Where: engine/runtime/src/runtime_swap.cpp.
- Rule or table: ARCH3-R031.

## Requests, RFP9 and the shutdown event

- Decision:
  - request_suspend and request_stop take effect only in the end_frame slot lifecycle_requests.
  - RFP9 is visited in every boundary slot and at every phase end.
  - The runtime emits the shutdown runtime.mem event itself, after the jobs stop and the frame state is released,
    before the memory root goes.
- Why: the brief places the RFP9 visits and leaves the emitter of WO-085's deferred event open.
- Where: engine/runtime/src/runtime_lifecycle.cpp `visit_suspend_point`, `runtime::on_lifecycle_requests`,
  `runtime::emit_shutdown_report`.
- Rule or table: ARCH3-R033; `failpoints` RFP9.

## Accessors beyond the brief

- Decision: these are added: `root_memory`, `frame_faulted`, `recoveries`, `snapshot_ticks`, `config`, `scope`,
  `discarded_results`, `swap_code`, the free functions `next_state` and `to_string`, and the `rt_event` enum.
- Why: the tests and the link (WO-097) need to read these, and the 15-row table is easier to check as a pure function.
- Where: engine/runtime/include/sl/runtime/runtime.hpp.
- Rule or table: ARCH3-R022.

## Open issues

- The tick-0 snapshot is taken before the host fills the world, so restoring to it gives an empty world.
- Per-system last_run is not rewound on restore.
- Under TSan, /proc/self/task includes the sanitizer's background thread from the first thread start on. The thread
  tests therefore read their baseline while a probe thread runs.

# WO-088 deviations: archetype storage (episode 092)

## component_info carries a type key; the registry maps types to ids

- Decision: `component_info` gains `type_key` (the address of `detail::type_anchor<T>`, nullptr for add_raw), and
  `component_registry` gains `id_of<T>()`, `find_key`, `contains` and `frozen()`. `add<T>` returns already_exists when
  T is already registered under another name, as add_raw does for a duplicate name.
- Why: the world's templates (`get<T>`, `add<T>`, `create_with`) must map T to its id without RTTI; the brief names
  only find(name). A constexpr anchor is not a mutable global (R-RT-GLOBAL).
- Where: engine/runtime/include/sl/runtime/ecs/component.hpp `component_info`, `component_registry::id_of`,
  engine/runtime/src/ecs_component_registry.cpp `component_registry::add_raw`.
- Rule or table: ARCH3-R106.

## add_raw refusal order and codes

- Decision: add_raw checks frozen (component_registry_frozen), empty name (invalid_argument), size 0 or above 2048,
  alignment not a power of two or above 64, null move or destroy, and the 1024-type limit (all component_invalid),
  then a duplicate name or type (already_exists).
- Why: the brief names component_registry_frozen and component_invalid only; invalid_argument and already_exists are
  the core codes for a malformed argument and a duplicate.
- Where: engine/runtime/src/ecs_component_registry.cpp `component_registry::add_raw`.
- Rule or table: ARCH3-R106, `error_codes`.

## layout_digest hashes a placeholder field count

- Decision: layout_digest hashes "sl-ecs-layout/1", the count, then per id the name, size, alignment and a u32 0 where
  the reflected field count will go; `type_info` is only forward-declared.
- Why: reflect.hpp (WO-087) has not landed; the digest format reserves the slot so joining the field walk changes the
  values but not the shape.
- Where: engine/runtime/src/ecs_component_registry.cpp `component_registry::layout_digest`.
- Rule or table: ARCH3-R106; open issue for WO-087.

## The background-job assertion needs world::set_job_system

- Decision: `world::set_job_system(const jobs::job_system *)` registers the job system; every accessor and structural
  call SL_DEBUG_ASSERTs `jobs_->current_job_priority() != background` when one is set, and nothing when none is.
- Why: `current_job_priority` is a member of job_system, not a free function, and the world has no other way to reach
  it.
- Where: engine/runtime/include/sl/runtime/ecs/world.hpp `world::set_job_system`, engine/runtime/src/ecs_world.cpp
  `world::check_access`.
- Rule or table: ARCH3-R109, `thread_safety`.

## The owner thread, wrong_thread and the guard order

- Decision: the owner is the thread that called `world::make`. Structural calls, restore_from and add_resource from
  any other thread return wrong_thread. check_structural tests owner thread, then the iteration guard (SL_DEBUG_ASSERT
  and structural_change_forbidden, so Release also refuses), then the phase (structural_change_forbidden), then the
  background-job assertion. Reads have no thread check (shared reads during a phase are allowed).
- Why: ARCH3-R109 forbids structural changes off the owner thread and inside phases but names no code for the thread
  case; wrong_thread is the `error_codes` row for it. Returning the error after the assert keeps Release safe.
- Where: engine/runtime/src/ecs_world.cpp `world::check_structural`, `world::check_access`.
- Rule or table: ARCH3-R109, `error_codes` wrong_thread, structural_change_forbidden.

## set adds when the component is missing; document writes stamp no changed tick

- Decision: `set` is structural-checked, replaces in place when the component is present (stamping the changed tick
  only for write_source::runtime) and adds it when missing (added = tick; changed = tick for runtime, 0 for document).
  `create_with` with one type twice returns invalid_argument.
- Why: the brief says a document write stamps no tick but not what set does on a missing component; adding keeps
  playback of document edits total.
- Where: engine/runtime/src/ecs_world_structural.cpp `world::set_raw`, `world::add_raw`, `world::create_raw`.
- Rule or table: ARCH3-R107, ARCH3-R111.

## Memory tags: ecs.chunks when registered, the default tag otherwise

- Decision: chunk slabs use the upstream's tag registry entry "ecs.chunks" when it exists, else the upstream's default
  tag; every other block (archetype objects, chunk and slab lists, transitions, location pages, resources) uses the
  default tag.
- Why: the tag registry is filled by WO-096 at runtime start and has no ecs.entities entry yet; a world built over an
  untagged resource must still work. The slab-pointer list is metadata, so the chunk tag counts exactly the slabs.
- Where: engine/runtime/src/ecs_world.cpp `chunk_tag_of`, `world::world`.
- Rule or table: ARCH3-R108, memory tags.

## Every world allocation goes through try_allocate, including metadata

- Decision: archetype objects, the archetype list, chunk lists, transition caches, location pages and resource blocks
  are allocated with `resource::try_allocate` into `detail::buffer<T>` (trivially copyable elements, memcpy growth);
  only restore_from's validation scratch uses std::vector on the global heap. The world object itself is
  `new (std::nothrow)`.
- Why: the pmr path asserts on exhaustion, so reserve-before-move needs a fallible allocator everywhere; it also makes
  the RFP0 sweep cover every allocation of a structural change.
- Where: engine/runtime/include/sl/runtime/ecs/world.hpp `detail::buffer`, engine/runtime/src/ecs_world_structural.cpp.
- Rule or table: ARCH3-R110.

## Limits and their codes

- Decision: more than 32 components in one archetype, more archetypes than world_config::max_archetypes, and a
  signature whose single row does not fit 16384 bytes (eight 2048-byte components) all return archetype_limit and
  change nothing. world::make returns invalid_argument for an unfrozen registry, max_entities 0 or max_archetypes
  outside 1..4096.
- Why: the brief names archetype_limit for the archetype count only; a row that cannot fit is the same kind of limit.
- Where: engine/runtime/src/ecs_world_structural.cpp `world::stage_archetype`, `world::resolve`,
  engine/runtime/src/ecs_world.cpp `world::make`.
- Rule or table: ARCH3-R107, ARCH3-R108, `limits`.

## Rows moved counts the moving row

- Decision: world_stats::last_rows_moved counts every row relocated by the latest successful structural change: an add
  or remove moves its own row (1) plus the swap-remove fill (0 or 1); a destroy moves only the fill; a create moves
  none. An in-place set is not structural and leaves the counters alone.
- Why: the brief asks for rows moved per structural change without defining it; counting the relocation itself is what
  the cost model needs.
- Where: engine/runtime/include/sl/runtime/ecs/world.hpp `world_stats`, engine/runtime/src/ecs_world_structural.cpp
  `world::note_change`, `world::fill_hole`.
- Rule or table: not covered (performance counter).

## Extra surface beyond the brief

- Decision: the world also exposes the raw API (create_raw, add_raw, remove_raw, set_raw, get_raw,
  get_unchecked_raw), `has`, a const `get`, `registry()`, `stats()`, `release_empty_chunks()` and the resource slots
  (add_resource_raw, resource_raw); archetype exposes `layout()`, `capacity()`, `row_count()`, `contains()` and
  `position_of()`; `added_ticks` and `changed_ticks` are const members returning mutable spans.
- Why: the templates are thin wrappers over the raw calls (reflection and the document layer need the raw form), the
  tests check the layout through `layout()`, and change detection writes ticks through a const archetype view.
- Where: engine/runtime/include/sl/runtime/ecs/world.hpp `world`, `archetype`.
- Rule or table: ARCH3-R107, ARCH3-R108.

## Resource errors

- Decision: add_resource returns already_exists for a duplicate key and invalid_argument for a malformed slot;
  resource<T> returns not_found for a missing key and invalid_argument when the stored type differs.
- Why: the brief names the calls but no codes; these are the core codes for the cases.
- Where: engine/runtime/src/ecs_world_resources.cpp `world::add_resource_raw`, `world::resource_raw`.
- Rule or table: not covered.

## capture_image and restore_from

- Decision: capture_image lists views (no copies) of the allocator state, every archetype in creation order with its
  non-empty chunks, the resources by key and the change tick. restore_from validates the image (dense chunks of this
  world's capacity, registered strictly ascending signatures, each alive entity placed exactly once), stages every
  archetype, chunk, location page and resource block, restores the entity allocator last, and only then moves the
  values in (memcpy or info.move; the image's owner still destroys its sources) and tears the old state down. It
  bumps the archetype generation and the version and keeps the image's change tick. An image that aliases the world
  being restored is not supported.
- Why: WO-095's snapshot uses only this API; staging everything first keeps restore all-or-nothing under RFP0
  (RT-INV-STORE-05 sweeps it).
- Where: engine/runtime/src/ecs_world_image.cpp `world::capture_image`, `world::restore_from`.
- Rule or table: ARCH3-R110, ARCH3-R111.

## Empty chunks stay until the boundary

- Decision: rows stay dense (removal fills the hole from the archetype's last row); trailing chunks that become empty
  stay with their archetype until `release_empty_chunks()` returns them to the per-world pool; pooled chunks are
  reused before a new slab is allocated, and slabs are released only when the world is destroyed.
- Why: ARCH3-R109 puts chunk release at the boundary; keeping slabs avoids allocator churn in steady state.
- Where: engine/runtime/src/ecs_world.cpp `world::release_empty_chunks`, `world::acquire_chunk`.
- Rule or table: ARCH3-R108, ARCH3-R109.

## Open: the gcc analyzer flags job_fn, not the store

- Decision: none taken here. With SL_ANALYZER=ON, gcc reports -Wanalyzer-null-argument at jobs.hpp:185, 186 and 190
  (the captureless lambdas in `job_fn::ops_for<T>`, through their static invokers) in every translation unit that
  builds a job_fn. That covers all of rt_unit_job (WO-082, WO-086) and, through the background-job guard case,
  store_guard_test.cpp. sl_runtime and the other store tests have zero analyzer findings. The fix belongs in
  jobs.hpp, which is outside WO-088's paths: named static member functions in place of the lambdas, or a
  documented suppression there. The store test keeps its job case, because RT-INV-STORE-07 covers background jobs.
- Where: engine/runtime/include/sl/runtime/jobs.hpp `job_fn::ops_for`; tests/unit/runtime/store_guard_test.cpp.
- Rule or table: RT-INV-STORE-07.

# WO-079 deviations: memory allocation contracts (episode 083)

Builder record for memory.hpp, src/memory_{registry,resource,tracking}.cpp, testing/allocator_contract.*,
testing/failing_resource.* and the six mem_*_test.cpp files. SL-ARCH-003 was not edited.

## Two upstreams: the backing of tracking_resource and the fallback of the pmr path

- Decision: `tracking_resource(name, default_tag, tags, backing)` takes the resource it allocates from (default
  std::pmr::new_delete_resource()); `resource::set_upstream` sets a separate fallback used only by do_allocate after
  try_allocate failed (default none, so the pmr path asserts). `upstream()` reads it back.
- Why: the brief names both "wraps an upstream" and "set_upstream"; with one pointer, a failed backing allocation would
  be retried on the same exhausted resource and "without one" could never happen for a tracking_resource.
- Where: memory.hpp `resource::set_upstream`, `resource::upstream`, `tracking_resource::tracking_resource`,
  `tracking_resource::backing`.
- Rule or table: ARCH3-R042, RT-INV-MEM-04.

## resource construction and accessors

- Decision: the protected constructor is `resource(name, default_tag = {}, const tag_registry *tags = nullptr)`;
  added `tags()` and `tag_label(tag)` (the registry name, else "untagged" or "tag#<id>") for reports. default_tag()
  and name() are noexcept.
- Why: the brief gives default_tag() and name() but not where they come from; the tag report and the leak order need
  tag names.
- Where: memory.hpp `resource`; src/memory_resource.cpp `resource::tag_label`.
- Rule or table: ARCH3-R042, ARCH3-R044.

## The pmr path is public as forward_allocate; do_* are final

- Decision: do_allocate calls the public `forward_allocate(bytes, align) noexcept`, which returns nullptr when the
  assert handler returns. do_allocate, do_deallocate and do_is_equal are `final` (and noexcept).
- Why: libstdc++ declares std::pmr::memory_resource::allocate returns_nonnull, so a nullptr through allocate() is
  undefined (UBSan reports it); RT-INV-MEM-04 observes the nullptr through forward_allocate. final keeps every
  allocator on the ARCH3-R042 path.
- Where: memory.hpp `resource::forward_allocate`; src/memory_resource.cpp.
- Rule or table: ARCH3-R041, ARCH3-R042.

## Blocks from the fallback upstream are remembered

- Decision: forward_allocate records each block it took from the upstream in a mutex-protected std::set; do_deallocate
  returns such a block to the upstream and every other block to release(). An atomic count skips the lock when none
  is live.
- Why: release() would otherwise hand an upstream block to the resource that never allocated it.
- Where: memory.hpp `resource::upstream_blocks_`; src/memory_resource.cpp `resource::do_deallocate`.
- Rule or table: ARCH3-R042.

## A 16-byte header in front of every tracked block

- Decision: tracking_resource takes size + max(align, 16) bytes aligned to max(align, 16) from its backing and puts a
  header {size, tag, log2 align, magic} in the 16 bytes before the user pointer. release reads tag and size from it in
  every build (SL_ASSERT on a foreign block, SL_DEBUG_ASSERT on a size or alignment mismatch) and clears it.
- Why: release(p, bytes, align) carries no tag and Release builds have no site table; per-tag counters need the tag.
  The cost is up to one alignment unit per block (4096 for a 4096-aligned block).
- Where: src/memory_tracking.cpp `block_header`, `tracking_resource::try_allocate`, `tracking_resource::release`.
- Rule or table: ARCH3-R043, ARCH3-R045.

## Nothrow allocation from any upstream

- Decision: `try_allocate_from(resource, bytes, align, tag, site)` and `release_to(...)` (public, memory.hpp): a
  mem::resource through try_allocate/release, new_delete_resource through nothrow aligned operator new/delete
  (out_of_memory on nullptr), any other pmr resource through allocate/deallocate, where an exception terminates at the
  noexcept boundary. Bookkeeping inside noexcept bodies (the site map, the upstream set, error messages) terminates
  the same way when the heap itself is exhausted.
- Why: no try/catch in the runtime (R-RT-THROW); ADR-0023 makes OOM an abort. WO-081 can reuse the helpers.
- Where: memory.hpp `try_allocate_from`, `release_to`; src/memory_resource.cpp.
- Rule or table: ARCH3-R010, ARCH3-R042, ADR-0023.

## Tag ids, validation and the failures counter

- Decision: registered tags are ids 1..256 (id 0 untagged), so the counter array has 257 slots. With a registry, a
  tag must be registered (id 0 included) and otherwise try_allocate is invalid_argument; without one any id up to 256
  is accepted. `failures` counts bad_alignment and backing exhaustion, not invalid_argument (no valid slot) and not
  RFP0 (counters unchanged). Added `tag_counters` and `totals()`; counters are relaxed atomics with a CAS max for the
  peak.
- Why: max_memory_tags (256) counts names; ARCH3-R045 requires a registry tag for tracked allocations.
- Where: memory.hpp `memory_tag`, `tag_counters`, `tracking_resource::counters`, `totals`.
- Rule or table: ARCH3-R045, `limits` max_memory_tags, RT-INV-MEM-02, RT-INV-MEM-04.

## tag_registry details

- Decision: checks in order: frozen (tag_registry_frozen), grammar (invalid_argument), reserved through add
  (tag_reserved), non-reserved through reserve_external (invalid_argument), duplicate (already_exists), capacity
  (out_of_range). Reserved means the first segment is `gpu` or `fabric` (so `gpu` alone too, `gpux.a` not). A second
  freeze succeeds. name() is "untagged" for id 0 and "unknown" for an unregistered id. Added contains(), size() and
  the constants runtime_tag_names and runtime_external_tag_names (the start-up list of WO-096). Names have no length
  limit (none in `limits`); storage is reserved to 256 so name() views stay valid.
- Why: the brief lists the errors but not their precedence or the meaning of the prefix.
- Where: memory.hpp `tag_registry`; src/memory_registry.cpp `insert`, `valid_name`, `reserved_name`.
- Rule or table: ARCH3-R045, `immutability` tag registry, RT-INV-MEM-05.

## Debug and sanitizer switches

- Decision: `debug_memory` is true when SL_RUNTIME_FAULTS=1 or NDEBUG is unset (Debug and every sanitizer build); it
  gates the fills and the site table. `asan_enabled` and the macro SL_RUNTIME_ASAN come from __SANITIZE_ADDRESS__ or
  __has_feature(address_sanitizer). Added `effective_alignment`, `effective_size` and the limit constants
  max_alignment, max_memory_tags, debug_fill_fresh and debug_fill_freed.
- Why: the brief says "Debug and sanitizer builds"; SL_RUNTIME_FAULTS already encodes exactly that.
- Where: memory.hpp.
- Rule or table: ARCH3-R046, ARCH3-R174, `limits`.

## tracking_resource fills but does not poison

- Decision: tracking_resource fills fresh blocks 0xCD and freed blocks 0xDD (debug_memory) and does not poison: it
  returns every block to its backing, which owns the range. RT-INV-MEM-06 checks poisoning through the
  poison/unpoison helpers on a buffer standing for a recycling resource's freed and reset ranges; WO-081's recycling
  allocators call them.
- Why: ARCH3-R046 asks recycling resources to poison; poisoning memory that a backing pool hands out again would
  produce false ASan reports.
- Where: src/memory_tracking.cpp `try_allocate`, `release`; tests/unit/runtime/mem_fill_poison_test.cpp.
- Rule or table: ARCH3-R046, RT-INV-MEM-06.

## Leak report

- Decision: leaks() sorts by (tag_label, file, line, size) and is empty in Release. The destructor logs one error
  event per live block, system runtime.mem, message "live block at resource destruction", fields resource, tag,
  tag_id, size, file and line; in Release (no site table) one event per tag with live blocks (fields blocks, size).
  The leaked blocks are not freed (they may still be in use).
- Why: the brief fixes the order and one event per block but not the fields or the Release behaviour.
- Where: src/memory_tracking.cpp `~tracking_resource`, `leaks`.
- Rule or table: ARCH3-R044, RT-INV-MEM-03.

## failing_resource

- Decision: it does not visit RFP0; fail_at is 1-based over all try_allocate calls (0 never fails); with `only` every
  call of that tag fails and fail_at is ignored. The injection check runs before the alignment check; served requests
  go to the upstream with the effective size and alignment. Added calls() and failed(); its name is
  "failing_resource" and its default tag is untagged.
- Why: the brief's "fails the fail_at-th ... (or every one of `only`)"; visiting the process-wide RFP0 would make it
  interfere with an armed tracking_resource.
- Where: engine/runtime/testing/failing_resource.hpp, failing_resource.cpp.
- Rule or table: `failpoints` RFP0, ARCH3-R020.

## Contract suite threads and owner_thread_only

- Decision: run_allocator_contract creates no thread (R-RT-PLATFORM covers testing/). owner_thread_only true means the
  suite is the resource's only user and checks exact tag-accounting deltas of a tracking_resource; false skips those
  checks so several threads may run the suite on one resource at once (mem_tracking_test does, four threads). All
  allocations carry r.default_tag(); the pmr step needs a default tag the resource accepts.
- Why: the brief names the flag but not its effect; threads outside src/platform_*.cpp are banned.
- Where: engine/runtime/testing/allocator_contract.hpp `contract_options`, allocator_contract.cpp.
- Rule or table: ARCH3-R035, ARCH3-R175, RT-INV-MEM-01, RT-INV-MEM-02.

## Tests that need the failpoints

- Decision: the two RFP0 cases of RT-INV-MEM-04 skip with a message when the failpoints are compiled out (Release);
  the no-upstream case exhausts the backing through failing_resource, so it runs in every build.
- Why: RFP0 exists only with SL_RUNTIME_FAULTS=1.
- Where: tests/unit/runtime/mem_failure_test.cpp.
- Rule or table: ARCH3-R020, RT-INV-MEM-04.

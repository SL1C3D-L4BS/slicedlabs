## The dump writes to stdout

- Decision: `sl_runtime_dump_contract` takes no argument and prints the contract to stdout; runtime-contract-lock.sh
  redirects it to build/runtime/contract-dump.json.
- Why: runtime-lint R-RT-PLATFORM forbids opening files anywhere in engine/runtime outside src/platform_*.cpp, tools
  included; the shell redirect keeps the output under build/ (R-RT-OUTPUT).
- Where: engine/runtime/tools/sl_runtime_dump_contract.cpp `main`; scripts/runtime/runtime-contract-lock.sh.

## Python-owned sections are added by contract_lock.py

- Decision: stress_matrix (cell and test file from stress_report.CELLS), the formats of hash-matrix.json,
  stress-matrix.json and ../scorecard.json (determinism_check.FORMAT, stress_report.FORMAT, scorecard.OUTPUT_FORMAT)
  and the header list compared with `layers` come from the Python tools and the file tree, not from the C++ dump.
- Why: those values are defined in Python or by the files on disk; duplicating them in C++ would create a second
  source the lock could not catch.
- Where: tools/runtime/contract_lock.py `python_sections`, `build_contract`, `layer_errors`.

## Normalised comparisons

- Decision: rt_states transitions compare as sorted (from, event, to) triples (the fourth column is prose); failpoints
  compare id, name and site (the outcome is prose the stress tests check); gate_evidence compares rows whose format is
  not "text"; stress_matrix compares cell and test; layers compare the header names (a parenthetical is dropped);
  lists of records are matched by their key (id, name, cell, file, phase or layer) so a line names the item.
- Why: the brief asks for each differing key path; prose columns are not code data (WO-076 dropped the outcome column).
- Where: tools/runtime/contract_lock.py `doc_contract`, `keyed_compare`, `compare`.

## Limits the code cannot expose carry "bound": false

- Decision: 14 rows are marked `"bound": false` (formulas steal_attempts_per_round and workers_default, the test tiers,
  SL_RUNTIME_STRESS_SCALE_default, gate_test_scale, gate_systems, injection_queue_capacity, canonical_nan_f32/f64 and
  os_thread_name_bytes); the lock skips them and fails when the dump defines one of them.
- Why: they are formulas, CMake or ctest values, or constants private to one source file; exporting them would need
  engine changes outside paths_allowed.
- Where: SL-ARCH-003 `limits`; contract_lock.py `doc_contract`, `check`.

## Config-backed limits and literal evidence formats

- Decision: limits that are runtime_config, swap_request or steal_options defaults are dumped from a
  default-constructed value; demo-report, f5 and schedule formats are literals in the dump (their writers keep the
  string in a .cpp or a test), fault, hashes and memreport formats come from code constants.
- Why: no header constant exists for those formats; the lock still binds the literal to the document.
- Where: sl_runtime_dump_contract.cpp `limits`, `contract`.

## Scorecard inputs: required and optional

- Decision: demo-report.json, memreport.json, f5.json and stress-matrix.json are required (absent fails the measure as
  `not_run`); hash-matrix.json and the sanitizer logs are optional (absent is `not_run` and does not fail); a
  compiled-out F5 ledger fails f5_bypassing; leaks counts memreport `leaks` entries; divergences counts divergent or
  missing hash-matrix cells plus a demo recovery whose hash differs; sanitizer reports use runtime-san.sh's pattern.
- Why: the brief names sanitizer logs outside check-full as optional; the matrix is check-full only (runtime-determinism);
  the other inputs come from runtime-demo, runtime-stress and the gate test that every gate run has.
- Where: tools/runtime/scorecard.py `score` and the measure functions.

## runtime-scorecard reruns runtime_gate_fabric_test in Debug

- Decision: the script builds sl_runtime_all_tests (debug) and reruns runtime_gate_fabric_test before scoring.
- Why: f5.json is rewritten by whichever preset ran the gate test last; a Release run leaves `enabled: false`, which
  measured nothing. The debug run (about 10 s) gives a measured F5 ledger.
- Where: scripts/runtime/runtime-scorecard.sh.

## Reconciliation scope

- Decision: rules stay as written except the R053 schema path (schemas/runtime/memreport.schema.json); departures are

  thread_safety notes, gate_evidence) is corrected, and code still to change is an open issue naming WO-101, a
  class-S fix order or Volume 17.
- Why: the brief keeps the rules ("descriptive; the rules stand"); a wrong file path is not a rule.
- Where: docs/arch/SL-ARCH-003-runtime-execution.md.

## main carries a scoped NOLINT for bugprone-exception-escape

- Decision: `main` of the dump tool has NOLINTNEXTLINE(bugprone-exception-escape) with its reason above it.
- Why: std::format and std::string may throw, engine/runtime forbids try and catch (R-RT-THROW), and the fabric tool's
  try/catch pattern is not available; an exception there terminates, as allocation failure does in every runtime body.
- Where: engine/runtime/tools/sl_runtime_dump_contract.cpp `main`.

## Sibling modules are loaded by path

- Decision: contract_lock.py and scorecard.py load determinism_check, scorecard, stress_report and contracts_check from
  tools/runtime by file path under the names runtime_<module>, and the tests load the tools the same way.
- Why: tools/fabric has contract_lock.py, scorecard.py and contracts_check.py too; under `just tools-test` (one
  discover over tools/) a plain import picks whichever was imported first (the test_contracts_check.py pattern).
- Where: tools/runtime/contract_lock.py and scorecard.py `_sibling`; test_contract_lock.py, test_scorecard.py.

## The lock is canonical JSON

- Decision: contract.lock.json is json.dumps(indent 2) of {format, sha256, contract} with sorted contract keys.
- Why: `just fmt-check-all` requires canonical JSON under schemas/ (the fabric lock has the same layout).
- Where: tools/runtime/contract_lock.py `lock_text`.

# WO-089 deviations: frame scheduler (episode 090)

## The namespace is sl::runtime

- Decision: every frame type lives in `sl::runtime` (frame.hpp), not in a `frame::` namespace.
- Why: the `thread_safety` table writes `frame::` as a module prefix; the brief names `sl::runtime::frame_scheduler`
  and the other runtime modules use the runtime namespace directly.
- Where: engine/runtime/include/sl/runtime/frame.hpp.
- Rule or table: `thread_safety`.

## retire_after returns result<void>

- Decision: `retire_after(std::uint32_t frames, std::function<void()> fn)` returns `result<void>`: wrong_thread off
  the owner thread, invalid_argument for frames 0 or an empty fn. The entry runs in the retire_after slot of frame
  `frame_index + frames`.
- Why: the brief writes void, but a zero delay or an empty function has to be refused, and a Debug-only assertion
  would let Release drop the call silently.
- Where: engine/runtime/src/frame_boundary.cpp `frame_scheduler::retire_after`.
- Rule or table: ARCH3-R098, `boundary_slots`.

## task_fn is an inline, non-consuming job_fn clone

- Decision: `task_fn` stores a noexcept body invocable as `T&` on `task_context&` in 48 bytes, aligned at most 16,
  through named static templates (invoke, relocate, destroy); it is invoked once per tick and not consumed.
- Why: a task runs every tick, so it cannot be a job_fn (consumed on run); the inline bound keeps run_frame free of
  upstream allocations (RT-INV-FRAME-04).
- Where: engine/runtime/include/sl/runtime/frame.hpp `task_fn`.
- Rule or table: ARCH3-R061, R051.

## Task names are copied

- Decision: add_task copies `task_desc::name` into a `std::string` in the task record; jobs get a view of it.
- Why: the caller's string_view need not outlive the schedule.
- Where: engine/runtime/src/frame_graph.cpp `frame_scheduler::add_task`.
- Rule or table: not covered.

## add_task refusals and the phases that take tasks

- Decision: tasks may go only to apply_inputs, pre_tick, tick, post_tick and observe. add_task returns wrong_thread
  off the owner thread, schedule_frozen after build, invalid_argument for begin_frame, present or end_frame, an empty
  body, more than 8 after ids, an unknown id or a cross-phase edge, and out_of_range for a 257th task of a phase.
- Why: begin_frame, present and end_frame are scheduler-owned steps; 8 is the job system's dependency limit per
  submit; 256 bounds the job handle table (max_tasks_per_phase).
- Where: engine/runtime/src/frame_graph.cpp `frame_scheduler::add_task`, frame.hpp `max_tasks_per_phase`.
- Rule or table: ARCH3-R063, R097, R099 (present stays a no-op), `limits` (max_systems_per_phase).

## A second build() succeeds

- Decision: build() after a successful build returns ok and changes nothing; run_frame before build is invalid_state.
- Why: build is idempotent; only add_task after build is an error (schedule_frozen).
- Where: engine/runtime/src/frame_graph.cpp `frame_scheduler::build`.
- Rule or table: ARCH3-R097.

## Hooks registered during run_frame are ignored

- Decision: add_boundary_hook and add_phase_end_hook ignore the call, with a Debug assertion, off the owner thread,
  during run_frame, or for an empty hook. retire_after may be called from a hook (it runs at a later frame).
- Why: appending to a hook list while it is iterated would invalidate it; the brief gives these functions no result.
- Where: engine/runtime/src/frame_boundary.cpp `frame_scheduler::add_boundary_hook`, `add_phase_end_hook`.
- Rule or table: ARCH3-R096, `boundary_slots`.

## boundary_context fields and the slot order of work

- Decision: `boundary_context` is {slot, frame_index, tick}. In each slot the scheduler's own action runs first
  (due retire_after entries in retire_after, `frame_arena::flip` in arena_flip), then the slot's hooks in
  registration order. end_frame drains main-affinity jobs and quiesces the job system before fault_check, and drains
  main-affinity jobs once more after the last slot.
- Why: the brief does not fix the fields or the action-versus-hook order; a hook of arena_flip must see the flipped
  arena; jobs a hook submits must finish inside the frame.
- Where: engine/runtime/src/frame_boundary.cpp `frame_scheduler::end_frame`, `run_slot`, `run_retired`.
- Rule or table: ARCH3-R066, R096, R098, `boundary_slots`.

## Phase end hooks

- Decision: phase end hooks run on the owner thread after begin_frame, apply_inputs, each tick's pre_tick, tick and
  post_tick, observe and present, with the logical tick at that point (post_tick before the tick advances); they do
  not run for end_frame, whose steps are the boundary slots.
- Why: the brief leaves the set open; end_frame already has nine hook slots.
- Where: engine/runtime/src/frame_graph.cpp `frame_scheduler::finish_phase`.
- Rule or table: ARCH3-R095.

## frame_stats semantics

- Decision: per-phase `jobs` is summed over the frame's ticks; `critical_path` is the static longest after-chain of
  the phase graph, 0 when the phase did not run; `wall` is two platform `clock.now()` reads per phase (diagnostic
  only, beyond the one wall sample per frame); dropped_ticks, dropped_ns and non_monotonic are cumulative since make.
- Why: the brief names the fields, not their accumulation.
- Where: engine/runtime/src/frame_stats.cpp `frame_scheduler::record_phase`, `close_stats`.
- Rule or table: ARCH3-R100, R080, R079.

## upstream_allocs and warmup_frames

- Decision: `upstream_allocs` is the frame's delta of the arena's upstream block allocations plus the scheduler's own
  container growth (retire list, frame inputs, copied result bytes). After `warmup_frames` (default 10) a non-zero
  delta logs a `runtime.frame` warning; it is not an error.
- Why: RT-INV-FRAME-04 needs one count that covers every allocation run_frame makes; the brief does not say what
  happens on a non-zero count.
- Where: engine/runtime/src/frame_stats.cpp `frame_scheduler::upstream_count`, `close_stats`.
- Rule or table: ARCH3-R051.

## Background results become frame inputs

- Decision: begin_frame drains `job_system::drain_results` into `frame_inputs()`; each result becomes an
  external_input with key {current tick, phase begin_frame, local_seq = drain index}, also given to the record sink
  through `on_external`. input_source is not polled.
- Why: polling the platform input source belongs to the input work orders; results are the only inputs this one owns.
- Where: engine/runtime/src/frame_scheduler.cpp `frame_scheduler::begin_frame`, `accept_result`.
- Rule or table: ARCH3-R094 (apply_inputs); otherwise not covered.

## Frame index, owner thread and make validation

- Decision: the frame index is the frame_clock's sample count. The owner is the thread that called make, assumed to
  be the job system's owner. make returns invalid_tick_rate (from fixed_stepper::make), invalid_argument for
  max_frame_delta <= 0 or `arena.workers() != jobs.worker_count()`, and out_of_memory when allocation fails.
- Why: the arena needs one set per worker plus the owner; run_main_affinity and quiesce are owner-thread calls.
- Where: engine/runtime/src/frame_scheduler.cpp `frame_scheduler::make`.
- Rule or table: ARCH3-R098, R079, `thread_safety`.

## Task failures do not fail run_frame

- Decision: a task that calls `ctx.fail` fails its job and cancels its dependents (job system semantics); run_frame
  still returns its stats. The fault_check slot runs the hooks only.
- Why: fault handling belongs to the fault work orders; this one gives them the slot.
- Where: engine/runtime/src/frame_graph.cpp `frame_scheduler::run_phase`.
- Rule or table: ARCH3-R096; open issue for the fault work orders.

## Clocks are not exposed for snapshots

- Decision: frame_clock, fixed_stepper and logical_clock are private members; there is no accessor for a snapshot
  contributor.
- Why: no snapshot API exists yet.
- Where: engine/runtime/include/sl/runtime/frame.hpp `frame_scheduler`.
- Rule or table: not covered; open issue for WO-098.

## No failpoint visits

- Decision: frame code visits no failpoints; there are no `SL_RUNTIME_FAULTS` branches.
- Why: the RFP9 failpoints belong to WO-096.
- Where: engine/runtime/src/frame_*.cpp.
- Rule or table: not covered; open issue for WO-096.

# WO-097 deviations: the Fabric link (ADR-0027)

## post_projection returns result<void>

- Decision: `world_link::post_projection` returns `result<void>`: projection_stale when the generation is not above the
  current one, invalid_argument when its domains differ from the link's.
- Why: the brief spells it `void` but also names projection_stale for it; a refusal the caller cannot see would be
  silently dropped.
- Where: engine/runtime/include/sl/runtime/bridge.hpp `world_link::post_projection`,
  engine/runtime/src/bridge_rebase.cpp `world_link::post_projection`.
- Rule or table: ARCH3-R157, ARCH3-R158.

## link_config carries the projection tag; attach checks it and the lifetime token

- Decision: `link_config` gains `mem::memory_tag projection_tag`; attach reports 0 bytes on it at once and returns the
  diagnostics' error when the tag was not reserved as external (tag_registry::reserve_external("fabric.projection")).
  attach also refuses an already expired `workspace_alive` token (invalid_argument); the Debug check that the token
  locks runs in each slot (`detail::check_alive`).
- Why: diagnostics::report_external takes a reserved tag, which the link cannot mint itself; failing in attach keeps the
  slots infallible. An expired token at attach is the same bug ARCH3-R159 catches later, found earlier.
- Where: engine/runtime/include/sl/runtime/bridge.hpp `link_config`, engine/runtime/src/bridge_ingest.cpp
  `world_link::attach`, `detail::check_alive`.
- Rule or table: ARCH3-R158, ARCH3-R159, limits (max_projections_held).

## The observe system reads every bound component; observe_component selects

- Decision: link.observe is added at attach with read access on every component in the binding registry;
  observe_component (owner thread, between frames) chooses which of them the system scans, adding one outbox buffer
  per observed component.
- Why: system_scheduler fixes a system's access at add, before any observe_component call; declaring the superset
  keeps the access guard exact without re-adding the system.
- Where: engine/runtime/src/bridge_ingest.cpp `world_link::attach`, `world_link::observe_component`,
  engine/runtime/src/bridge_observe.cpp `detail::observe`.
- Rule or table: ARCH3-R154, ARCH3-R151.

## Bound components: one per Fabric type, trivially copyable, of their reflected size

- Decision: binding_registry refuses a second component for a type and a second binding for a component
  (already_exists); attach refuses a bound component the world does not know, that is not trivially relocatable, whose
  size differs from its reflected type, or that is larger than 2048 bytes (invalid_argument).
- Why: the link writes component bytes through set_raw from a reflected conversion into a fixed 64-byte-aligned scratch;
  one component per type keeps ingest, diff and observe one-to-one.
- Where: engine/runtime/src/bridge_source.cpp `binding_registry::add`, engine/runtime/src/bridge_ingest.cpp `usable`.
- Rule or table: ARCH3-R151, ARCH3-R133.

## Spawn values start from zero bytes; rebase updates keep the runtime-only bytes

- Decision: an ingested or rebase-created entity's component is built from zeroed bytes plus the binding's
  `from_value`; a rebase update copies the entity's current bytes and overwrites only the bound fields.
- Why: fields that are not bound (transient) have no document value; zero is the defined start, and an update must not
  clobber runtime state the document does not own.
- Where: engine/runtime/src/bridge_ingest.cpp `detail::spawn_entries`, engine/runtime/src/bridge_rebase.cpp
  `update_record`.
- Rule or table: ARCH3-R153, ARCH3-R157, ARCH3-R150.

## Spawn key: the command buffer numbers the spawns; values are written after the flush

- Decision: one command buffer is opened at {tick, end_frame, link system index (its id before build), 0, 0} and
  spawn() is called in load_plan order, so the buffer's own local_seq is the spawn's position among the entries spawned
  (load_plan order, skipping mapped and unbound records). After the flush each entity's bound component is set with
  write_source::document and the pair is recorded in the entity_map.
- Why: command_buffer is typed only and assigns local_seq itself; the brief's "load_plan index" is kept as an order,
  not as the literal number. A document write stamps no changed tick, so the first observe drops the rows as echoes.
- Where: engine/runtime/src/bridge_ingest.cpp `detail::spawn_entries`, `detail::link_index`.
- Rule or table: ARCH3-R153, ARCH3-R160, determinism (ordered_key).

## Outbox order: record id, then path_segment ordering

- Decision: drained changes are ordered by record id (its bytes) and then by `fabric::path` compared with path_segment's
  operator<=>, rather than by encoded path bytes.
- Why: codec.hpp is not on the R-RT-FABRIC list for engine/runtime; the path ordering is total and defined by value.hpp.
- Where: engine/runtime/src/bridge_source.cpp `change_less`, `outbox::drain`.
- Rule or table: ARCH3-R154, determinism (outbox).

## Projection bytes are a body payload measure

- Decision: `body_bytes` counts payload: bool 1; uint, nint, f64 8; f32 4; string and bytes their length; id 16;
  digest 33; containers the sum of their children plus 4 per struct field or variant case and 16 plus the order key per
  oset entry. `projection_bytes` sums it over the projection's records. The external report (current plus pending) is taken on
  the owner thread at ingest and at the end of each projection_rebase slot, so after a rebase it is the current
  projection's bytes; post_projection (any thread) does not report.
- Why: SLB/1 encoded length needs codec.hpp (off-list); the gate needs a deterministic size that grows with content.
- Where: engine/runtime/src/bridge_source.cpp `body_bytes`, `projection_bytes`, engine/runtime/src/bridge_rebase.cpp
  `detail::report_projection_bytes`.
- Rule or table: ARCH3-R158.

## Records of no document come first

- Decision: load_plan lists records that belong to no document under the null document id, before every document.
- Why: the null id sorts lowest, so "document ascending" places them first and keeps the plan total.
- Where: engine/runtime/src/bridge_source.cpp `document_source::make`.
- Rule or table: ARCH3-R152.

## A faulted frame and a refused proposal

- Decision: the flush slot treats the frame as faulted when system_scheduler::failures() moved since the last flush or
  last_flush() holds an error, and then clears the outbox. A patch is counted in proposed_patches and proposed_changes
  when it is handed to the sink; a propose_from_observation error, a sink refusal or changes with no current projection
  each add 1 to rejected. Nothing fails the frame.
- Why: the scheduler exposes those two signals only; counting at hand-off keeps the counters independent of the sink.
- Where: engine/runtime/src/bridge_flush.cpp `detail::flush_observations`.
- Rule or table: ARCH3-R155, ARCH3-R161.

## Echo reference and domains

- Decision: observed values are compared with the binding-normalised value of the current projection's record
  (optional fields with their defaults applied), cached per record at ingest and rebase. A projection's domains must
  equal the link's configured domains (sorted) for ingest and post_projection (invalid_argument otherwise). A record
  whose rebase conversion fails is left as it was.
- Why: from_value/to_value applies defaults, so a raw body comparison would report defaulted fields as changes; one
  domain set keeps diff and scope checks meaningful.
- Where: engine/runtime/src/bridge_ingest.cpp `detail::cache_record`, `detail::same_domains`,
  engine/runtime/src/bridge_rebase.cpp `apply_diff`.
- Rule or table: ARCH3-R154, ARCH3-R157.

## Extra surface

- Decision: besides the brief's members the link exposes `projections_held`, `current_generation`, `system_id`,
  `outbox`, `body_bytes`/`projection_bytes`, null_sink's counters and last patch, binding_registry's `entry_of`,
  `find_component`, `entries`, `size`, and the testing helpers (`fabric_host` edit and id helpers, `link_rig`).
  There are no failpoints.
- Why: the invariant tests need to observe held projections, the outbox in isolation and the reported bytes; none of it
  hands out a Fabric store handle (RT-INV-BND-08).
- Where: engine/runtime/include/sl/runtime/bridge.hpp, engine/runtime/testing/fabric_host.hpp.
- Rule or table: ARCH3-R148, ARCH3-R177.

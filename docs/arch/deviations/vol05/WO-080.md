# WO-080 deviations: synchronization primitives (episode 087)

## spin_limit is a named constant of sync.hpp

- Decision: `sl::runtime::spin_limit = 64` is an `inline constexpr std::uint32_t` in sync.hpp and the default argument
  of `spin_wait(std::uint32_t limit = spin_limit)`; the brief writes the literal 64.
- Why: ARCH3-R174 takes the value from the `limits` table; one name lets WO-082 and WO-086 use the same bound and
  lets the test assert it.
- Where: engine/runtime/include/sl/runtime/sync.hpp `spin_limit`, `spin_wait`.
- Rule or table: ARCH3-R060, ARCH3-R174, `limits` spin_limit.

## A spin step is std::this_thread::yield

- Decision: each successful `spin_wait::spin()` calls `std::this_thread::yield()`; there is no CPU pause hint.
- Why: a pause needs inline assembly (R-RT-FENCE) or `<immintrin.h>`/`<x86intrin.h>` (R-RT-MATH); yield is portable
  and keeps a spinning waiter from starving the thread it waits for.
- Where: sync.hpp `spin_wait::spin`.
- Rule or table: ARCH3-R057, ARCH3-R060.

## job_counter::waiters() and the source layout

- Decision: job_counter has one member beyond the brief, `std::uint32_t waiters() const noexcept` (threads inside
  wait_zero now). cpu_fence and job_counter live in src/sync_fence.cpp, event_count in src/sync_event_count.cpp,
  spin_wait is inline in the header.
- Why: RT-INV-SYNC-02 must know that a waiter is registered before it calls reset(); polling reset() itself would
  release the waiter it tries to observe. The brief names only the two source files.
- Where: sync.hpp `job_counter::waiters`; src/sync_fence.cpp; tests/unit/runtime/sync_counter_test.cpp.
- Rule or table: ARCH3-R059, RT-INV-SYNC-02.

## Every atomic operation of the primitives is seq_cst

- Decision: sync_fence.cpp and sync_event_count.cpp use the default order (seq_cst) for every load, RMW, store, wait
  and notify; no explicit memory_order appears in engine code, so no `// pairs:` comment is needed there. The relaxed
  payload stores and loads of RT-INV-SYNC-05 carry `// pairs:` comments naming the publishing and waiting operation.
- Why: ADR-0024 asks for seq_cst on contended operations and ARCH3-R060 for a seq_cst epoch and sleeper count; the
  counters are contended by design and the cost is not measurable at this tier.
- Where: src/sync_fence.cpp, src/sync_event_count.cpp; tests/integration/runtime/sync_publish_test.cpp `payload`.
- Rule or table: ARCH3-R058, ARCH3-R060.

## cpu_fence and job_counter edge semantics

- Decision: `cpu_fence(0)` is released at construction; `signal(n)` with n above the remaining count clamps to zero
  (and releases); a signal after the release changes nothing. `job_counter::sub(n)` with n above the value is a Debug
  assertion and clamps to zero in Release; reaching zero notifies all waiters. `reset()` stores zero and notifies, so a
  waiter that registers between the waiter check and the store returns. wait_zero returns once it observes zero; a
  zero that is followed by add() before a parked waiter runs is not observed, and the waiter parks again.
- Why: the brief leaves over-signalling, underflow and the reset race open; clamping keeps the counter from wrapping
  to 2^32 - 1, which would turn a bug into a hang.
- Where: src/sync_fence.cpp `cpu_fence::signal`, `job_counter::sub`, `job_counter::reset`, `spin_then_park`.
- Rule or table: ARCH3-R059.

## event_count always advances the epoch

- Decision: notify_one and notify_all advance the epoch even with no sleeper and call `std::atomic::notify_*` only
  when the sleeper count is non-zero. The epoch is `std::atomic<std::uint64_t>`, which libstdc++ parks through its
  proxy wait (not a direct 32-bit futex). wait(key) withdraws the registration after the epoch moved.
- Why: incrementing first and reading the sleeper count second is the seq_cst Dekker pair with prepare_wait (sleeper
  count first, epoch second), so either the notifier sees the sleeper or the sleeper sees the new epoch; the key type
  of the brief is 64 bits and cannot wrap in practice. The increment line of notify_one carries `// neg-lost-wakeup`.
- Where: src/sync_event_count.cpp `event_count::notify_one`, `notify_all`, `prepare_wait`, `wait`.
- Rule or table: ARCH3-R060, RT-INV-SYNC-04.

## Tests create threads with std::thread, not the platform thread_factory

- Decision: the sync tests run waiters in std::jthread (a small `bounded_thread` wrapper per file whose completion is
  a `std::future::wait_for(5 s)`), as the brief says; they do not use `thread_factory` from platform.hpp.
- Why: R-RT-PLATFORM covers engine/runtime only and the brief allows test threads; WO-080 depends on WO-076 only, so
  its tests must not need WO-078's platform headers. Each test file holds its own copy of the wrapper because only
  sync_*_test.cpp files are in paths_allowed.
- Where: tests/unit/runtime/sync_*_test.cpp, tests/integration/runtime/sync_*_test.cpp `bounded_thread`.
- Rule or table: ARCH3-R035, ARCH3-R014.

## RT-INV-SYNC-04: rounds and the 5 s bound

- Decision: the 1e6 interleavings are 8 seeded rounds (base seed 0x5EED0870004, round r adds r << 4) of
  1e6 x scale / 8 items, each round one producer (notify_one, every 16th draw notify_all, every 32nd a yield) and three
  consumers (take, else prepare_wait, re-check, yield on every 8th draw, then wait or cancel_wait). event_count::wait
  has no timeout, so "every wait bounded at 5 s" is a watchdog: a round fails when no item is taken for 5 s, then sets
  abort and calls notify_all so every thread can be joined; each thread must then finish within 5 s. Stripping the
  `// neg-lost-wakeup` line makes all three cases of the file fail (checked locally with a scratch build).
- Why: the brief fixes the total, the seeding and the 5 s bound but not the shape of a round.
- Where: tests/integration/runtime/sync_eventcount_test.cpp `run_round`, `consume`, `produce`.
- Rule or table: ARCH3-R060, RT-INV-SYNC-04, `limits` SL_RUNTIME_STRESS_SCALE_default.

## RT-INV-SYNC-05: how "spins at most spin_limit before parking" is shown

- Decision: the waits expose no spin count, so the invariant is shown three ways: spin_wait stops after exactly its
  limit (spin_limit by default); a spin-then-park loop built from spin_wait and event_count parks after exactly
  spin_limit spins; and a waiter blocked about 200 ms on each primitive (cpu_fence, job_counter, event_count,
  counting_semaphore) uses less than half its wall time on the CPU (clock_gettime CLOCK_THREAD_CPUTIME_ID), i.e. it
  parked. Publication runs 2000 x scale rounds per primitive with 64 plain words (a missing happens-before is a TSan
  report) and 16 relaxed atomic words (checked by value); for event_count the key is taken before the producer starts.
- Why: the brief's API has no hook to count spins inside a wait; adding one would widen the public surface.
- Where: tests/integration/runtime/sync_publish_test.cpp `publish_rounds`, `parks`; sync.hpp `spin_wait`.
- Rule or table: ARCH3-R058, ARCH3-R060, RT-INV-SYNC-05.

## No failpoint in the sync area

- Decision: no primitive visits a failpoint, so there is no `#if SL_RUNTIME_FAULTS` branch in the sync sources.
- Why: SL-ARCH-003 `failpoints` names no sync site (RFP4 stalls belong to the worker loop of WO-082).
- Where: src/sync_fence.cpp, src/sync_event_count.cpp.
- Rule or table: ARCH3-R020, `failpoints`.
